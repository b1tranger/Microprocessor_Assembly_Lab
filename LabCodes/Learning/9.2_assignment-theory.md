# Three-Variable Extremum Extraction and Data Output Architecture (9.2_assignment.asm)

Finding the maximum, median, and minimum among three values is a foundational computer science problem. In 8086 assembly, implementing this multi-way decision tree requires strict register budgeting, flag-aware branching, and a clear distinction between byte-level character output (`AH=02h`) and string output (`AH=09h`). This document analyzes [`9.2_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm), explaining its intended 3-number sorting design, exposing critical syntax and architectural bugs, and providing a clean, working model.

## 1. Architectural Overview and Program Intent

The intended goal of [`9.2_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm) is to accept three single-digit values ($A$, $B$, $C$) from the user, determine the relationships between them, and identify the **largest**, **middle**, and **smallest** values.

```
       [Input A, B, C]
              |
         Compare A & B
        /             \
    A > B             A < B
    /                     \
Compare A & C         Compare B & C
```

In the `.data` segment ([`9.2_assignment.asm#L6-L16`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L6-L16)), variables are defined to store the results and labels:
- `largest db ?`, `l_out db ' is largest$'`
- `middle db ?`, `m_out db ' is middle$'`
- `smallest db ?`, `s_out db ' is smallest$'`
- `num1 db ?`, `num2 db ?`, `num3 db ?`

However, the code remains unfinished and suffers from syntax violations and severe runtime memory hazards.

## 2. Decision Tree Architecture for Three Numbers

### Permutation Complexity ($3! = 6$ Orders)

When ordering three distinct values ($A, B, C$), there are $3! = 3 \times 2 \times 1 = 6$ possible permutations:

| Case | Ordering | Largest | Middle | Smallest |
| :---: | :---: | :---: | :---: | :---: |
| 1 | $A > B > C$ | $A$ | $B$ | $C$ |
| 2 | $A > C > B$ | $A$ | $C$ | $B$ |
| 3 | $B > A > C$ | $B$ | $A$ | $C$ |
| 4 | $B > C > A$ | $B$ | $C$ | $A$ |
| 5 | $C > A > B$ | $C$ | $A$ | $B$ |
| 6 | $C > B > A$ | $C$ | $B$ | $A$ |

*(Note: Additional cases exist when elements are equal, such as $A = B$, $B = C$, or $A = B = C$.)*

### Optimal Tournament Model (2 to 3 Comparisons)

To find only the **largest** of 3 numbers:
1. Compare $A$ and $B$: Winner is $\max(A, B)$.
2. Compare winner with $C$: Winner is $\max(A, B, C)$.
3. **Total comparisons required**: Exactly 2 comparisons.

To find **all three** (largest, middle, smallest):
- Exactly 2 to 3 comparisons are required depending on intermediate branch paths.

## 3. Forensic Analysis of Bugs in `9.2_assignment.asm`

### Bug 1: Illegal Identifiers Starting with Digits (`1_is_big`, `2_is_big`)

In [`9.2_assignment.asm#L83-L84`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L83-L84) and [`#L90`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L90):
```assembly
jg  1_is_big
jl  2_is_big
...
1_is_big:
...
2_is_big:
```

> [!WARNING]
> In Intel 8086 assembly (MASM, TASM, and EMU8086), **symbolic labels and variable names cannot begin with a decimal digit**.
> Valid label names must start with a letter (`A-Z`, `a-z`), underscore (`_`), or question mark (`?`).
> Names like `1_is_big` trigger syntax errors: `Error: Symbol expected` or `Illegal character in identifier`.

**Correction**: Rename labels to `num1_is_big` or `a_is_big`.

---

### Bug 2: Undefined Label Reference (`jl 3_is_big`)

In [`9.2_assignment.asm#L102`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L102):
```assembly
cmp al, ah
jg  1_is_big_again
jl  3_is_big            ; Jump to undefined label!
je  both_are_equal
```

Notice that label `3_is_big:` **is never defined anywhere in the source file**.
- During the second assembly pass, the assembler attempts to resolve the address of `3_is_big`.
- When not found, assembly aborts with fatal error: `Undefined symbol: 3_IS_BIG`.

### Bug 3: The Un-terminated String Display Hazard (`AH=09h` on Single Byte `largest`)

In [`9.2_assignment.asm#L110-L113`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L110-L113):
```assembly
mov ah, 9
lea dx, largest
int 21h
```

Let's look at the declaration of `largest` in the data segment ([`9.2_assignment.asm#L11`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L11)):
```assembly
largest db ?
l_out db ' is largest$'
```

> [!CAUTION]
> **Memory Hazard**:
> Service `INT 21h, AH=09h` expects `DS:DX` to point to a string terminated by a dollar sign (`$`).
> `largest` is declared as a **single uninitialized byte** (`db ?`) without a trailing `$`.
> 
> Because `largest` is immediately followed in memory by `l_out db ' is largest$'`:
> 1. Calling `AH=09h` with `DX = offset largest` will print the byte inside `largest`, and then **immediately continue printing `l_out`** (`" is largest"`), because the first `$` it encounters is at the end of `l_out`!
> 2. Then, line 114 executes:
>    ```assembly
>    mov ah, 9
>    lea dx, l_out
>    int 21h
>    ```
>    This prints `l_out` a **second time**!
> 3. Result on screen if input is `7`: `7 is largest is largest`!

### Bug 4: Missing DX Register Loads Before `INT 21h` in Fallthrough Blocks

Examine lines 126–141 in [`9.2_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L126-L141):
```assembly
2_is_big:
    mov ah, 9
    ;lea dx, b          ; Commented out!
    int 21h             ; Prints whatever garbage DX pointed to previously!

both_are_equal:
    mov ah, 9
    ;lea dx, c          ; Commented out!
    int 21h             ; Prints whatever garbage DX pointed to previously!
```

Because `lea dx` was commented out, `DX` still contains the pointer from the preceding string operation (`l_out` or newline character). Calling `int 21h` executes DOS string print on stale register state.

In [`9.2_assignment.asm#L145-L147`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L145-L147):

## 4. Data Output Mechanics: Character Display (`AH=02h`) vs. String Display (`AH=09h`)

| Feature | DOS Service `AH=01h` | DOS Service `AH=02h` | DOS Service `AH=09h` |
| :--- | :--- | :--- | :--- |
| **Operation** | Read Character | Write Single Character | Write String |
| **Input Register** | None (Returns char in `AL`) | `DL = ASCII character` | `DX = Offset of string` |
| **Termination Requirement** | N/A | None (Single byte only) | Must be terminated with `'$'` |
| **Best Used For** | Keyboard input | Displaying single variables (`num1`, `largest`) | Fixed text messages (`"Enter A: "`) |

### How to Properly Output a Single-Byte Variable

To display the value stored in variable `largest` without modifying memory:
```assembly
mov ah, 2             ; DOS Service 02h: Output single character
mov dl, largest       ; Load ASCII character into DL
int 21h               ; Display character
```
Then follow with `AH=09h` for the message string:
```assembly
mov ah, 9
lea dx, l_out         ; Points to ' is largest$'
int 21h
```

## 5. Complete Trace of the Decision Logic

```
                    [ Start ]
                        |
                  Compare A and B
                 /               \
            (A >= B)            (B > A)
              /                     \
       Compare A and C          Compare B and C
       /             \          /             \
   (A >= C)        (C > A)   (B >= C)        (C > B)
      |               |         |               |
Max = A            Max = C   Max = B         Max = C
```

This ensures that every potential permutation is cleanly resolved in at most **two conditional checks**.

## 6. High-Level Language (C/C++) Equivalence

```c
#include <stdio.h>

int main() {
    char a, b, c, largest;

    printf("Enter the value of A: ");
    a = getchar(); getchar();
    printf("Enter the value of B: ");
    b = getchar(); getchar();
    printf("Enter the value of C: ");
    c = getchar();

    // Tournament comparison
    if (a >= b) {
        if (a >= c) {
            largest = a;
        } else {
            largest = c;
        }
    } else {
        if (b >= c) {
            largest = b;
        } else {
            largest = c;
        }
    }

    putchar('\n');
    putchar(largest);
    printf(" is largest\n");

    return 0;
}
```

## 7. Corrected, Fully Working Assembly Implementation

Below is the fully debugged, robust version of `9.2_assignment.asm` with legal label identifiers, proper single-character output, and clean program termination:

```assembly
.model small
.stack 100h

.data
    prompt_a db 'Enter the value of A: $'
    prompt_b db 10, 13, 'Enter the value of B: $'
    prompt_c db 10, 13, 'Enter the value of C: $'

    msg_largest db ' is largest$', 10, 13

    num1 db ?
    num2 db ?
    num3 db ?
    largest db ?

.code
main proc
    mov ax, @data
    mov ds, ax

    ; Read Num1
    mov ah, 9
    lea dx, prompt_a
    int 21h
    mov ah, 1
    int 21h
    mov num1, al

    ; Read Num2
    mov ah, 9
    lea dx, prompt_b
    int 21h
    mov ah, 1
    int 21h
    mov num2, al

    ; Read Num3
    mov ah, 9
    lea dx, prompt_c
    int 21h
    mov ah, 1
    int 21h
    mov num3, al

    ; --- Comparison Tournament ---
    mov al, num1
    mov bl, num2
    cmp al, bl
    jae check_a_c           ; If A >= B, test A against C

check_b_c:
    ; Here B > A, now test B against C
    mov bl, num2
    mov cl, num3
    cmp bl, cl
    jae b_is_max            ; If B >= C, then B is maximum
    mov al, num3            ; Otherwise C is maximum
    mov largest, al
    jmp display_result

b_is_max:
    mov largest, bl
    jmp display_result

check_a_c:
    ; Here A >= B, now test A against C
    mov al, num1
    mov cl, num3
    cmp al, cl
    jae a_is_max            ; If A >= C, then A is maximum
    mov al, num3            ; Otherwise C is maximum
    mov largest, al
    jmp display_result

a_is_max:
    mov largest, al

display_result:
    ; Newline before result
    mov ah, 2
    mov dl, 10
    int 21h
    mov dl, 13
    int 21h

    ; Display the largest character via AH=02h
    mov ah, 2
    mov dl, largest
    int 21h

    ; Display string ' is largest' via AH=09h
    mov ah, 9
    lea dx, msg_largest
    int 21h

exit:
    mov ah, 4ch
    int 21h

main endp
end main
```
