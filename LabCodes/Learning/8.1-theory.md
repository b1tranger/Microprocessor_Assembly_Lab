## 1. Architectural Overview and Program Purpose

The intended pipeline of [`8.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-8_Labtest-1/8.1.asm) consists of four sequential stages:
1. **User Input (`INT 21h, AH=01h`)**: Reads an ASCII character from the keyboard into `AL` and stores it into variable `char`.
2. **Case Inversion (`XOR AL, 32`)**: Toggles the 5th bit (bit index 5, mask `20h`), turning uppercase ASCII characters into lowercase, and vice versa. Displays the converted character via `INT 21h, AH=02h`.
3. **Circular Left Rotation (`ROL AL, 1`)**: Rotates the converted 8-bit pattern left by 1 bit, wrapping the most significant bit (MSB) into the least significant bit (LSB) and the Carry Flag (`CF`).
4. **Hexadecimal Output Display**: Splitting the 8-bit rotated value into two 4-bit nibbles (high nibble via shift right, low nibble via bitwise mask `0Fh`), converting each nibble into printable ASCII hex (`0-9`, `A-F`), and outputting them sequentially via a helper procedure.

---

## 2. Case Inversion Mechanics (`XOR 32` / `XOR 20h`)

In standard ASCII encoding:
- Uppercase letters `'A'` to `'Z'` occupy hexadecimal range `41h` to `5Ah` (`0100 0001b` to `0101 1010b`).
- Lowercase letters `'a'` to `'z'` occupy hexadecimal range `61h` to `7Ah` (`0110 0001b` to `0111 1010b`).

Notice that the binary representation of uppercase and lowercase variants differs **only at Bit 5** (value $2^5 = 32 = 20\text{h}$):

| Character | ASCII Decimal | ASCII Hex | Binary Representation |
| :--- | :--- | :--- | :--- |
| `'A'` | `65` | `41h` | `01`**`0`**`0 0001b` |
| `'a'` | `97` | `61h` | `01`**`1`**`0 0001b` |
| `'B'` | `66` | `42h` | `01`**`0`**`0 0010b` |
| `'b'` | `98` | `62h` | `01`**`1`**`0 0010b` |

Executing `xor al, 32` toggles Bit 5:
- If Bit 5 is `0` (uppercase), `0 XOR 1 = 1` $\rightarrow$ becomes lowercase.
- If Bit 5 is `1` (lowercase), `1 XOR 1 = 0` $\rightarrow$ becomes uppercase.

## 3. Bitwise Circular Shift (`ROL`) vs Logical Shifts (`SHL`/`SHR`)

The `ROL` (Rotate Left) instruction circularly shifts all bits in the operand to the left:
```
           +-----------------------------+
           |                             |
           v                             |
CF <--- [Bit 7] <--- [Bit 6..1] <--- [Bit 0]
```
- The bit departing from the MSB (Bit 7) is fed simultaneously into the **Carry Flag (`CF`)** and wrapped around into the **LSB (Bit 0)**.
- Unlike `SHL` (which injects zeros at Bit 0 and discards Bit 7 after setting CF), `ROL` preserves all bit values without losing information.
- **Important 8086 Rule**: `ROL` is a native CPU machine instruction executed internally by the ALU. It requires **no software interrupt** (`INT 21h`).

## 4. Hexadecimal Output Architecture (Nibble Extraction & ASCII Mapping)

An 8-bit byte contains two 4-bit hexadecimal digits called **nibbles**:
- **High Nibble**: Bits 7..4
- **Low Nibble**: Bits 3..0

```
Byte: [ b7 b6 b5 b4 | b3 b2 b1 b0 ]
       \___________/ \___________/
        High Nibble   Low Nibble
```

### Nibble Extraction Mechanics

1. **High Nibble Extraction**:
   Shift right by 4 positions. In standard 8086 assembly, immediate shift counts greater than 1 require the `CL` register:
   ```assembly
   mov al, bin_char
   mov cl, 4
   shr al, cl          ; AL now contains [0000 | b7 b6 b5 b4] (range 00h - 0Fh)
   ```
2. **Low Nibble Extraction**:
   Mask out the high nibble using a bitwise AND:
   ```assembly
   mov al, bin_char
   and al, 0Fh         ; AL now contains [0000 | b3 b2 b1 b0] (range 00h - 0Fh)
   ```

### ASCII Conversion Arithmetic (`+48` vs. `+7`)

A raw nibble value ranges from $0$ to $15$ ($0\text{h}$ to $0\text{Fh}$). To print it, we must map:
- $0 \dots 9 \rightarrow \text{'0'} \dots \text{'9'}$ (ASCII `30h` to `39h` / $48$ to $57$)
- $10 \dots 15 \rightarrow \text{'A'} \dots \text{'F'}$ (ASCII `41h` to `46h` / $65$ to $70$)

```
Raw Nibble:    0    1  ...   9   |  10   11   12   13   14   15
+ 48 ('0'):   48   49  ...  57   |  58   59   60   61   62   63
                                 |  ':'  ';'  '<'  '='  '>'  '?'
Gap to 'A'-'F' (65 - 58 = 7):    | + 7  + 7  + 7  + 7  + 7  + 7
Final ASCII: '0'  '1'  ...  '9'  | 'A'  'B'  'C'  'D'  'E'  'F'
             (48) (49)     (57)  | (65) (66) (67) (68) (69) (70)
```

The conversion algorithm requires:
```assembly
print_hex proc
    add al, 48          ; Step 1: Base offset for '0'-'9'
    cmp al, 57          ; Step 2: Compare against ASCII '9'
    jbe is_digit        ; If <= 57 ('9'), conversion is complete
    add al, 7           ; Step 3: Bridge the 7-character gap between '9' and 'A'
is_digit:
    mov dl, al
    mov ah, 02h
    int 21h
    ret
print_hex endp
```

## 5. Dissecting the Bugs in `8.1.asm`

### Bug 1: Why `msg3` Prints Multiple Times (The Lingering `AH=09h` Trap)

Consider lines 70 to 76 in [`8.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-8_Labtest-1/8.1.asm#L70-L76):
```assembly
70:     mov dx,  offset msg3
71:     mov ah, 09h
72:     int 21h  
73:       
74:     mov al, new_char
75:     rol al, 1
76:     int 21h           ; <--- FATAL BUG: Unintended DOS interrupt
```

1. Lines 70–72 stage `AH = 09h` and `DX = offset msg3`, then trigger `int 21h`. The string `"Hex code after rotate left = "` prints.
2. Lines 74–75 load `AL` and execute `rol al, 1`. The `ROL` instruction only modifies `AL` and CPU flags (`CF`, `OF`).
3. **Crucial insight**: Neither `rol` nor `mov al, new_char` touches `AH` or `DX`!
4. Therefore, at line 76:
   - `AH` is **still `09h`**
   - `DX` is **still `offset msg3`**
5. Line 76 triggers `int 21h`. DOS reads `AH = 09h`, looks at `DX`, and executes the string printing service a **second time**, duplicating `msg3` on screen!

---

### Bug 2: Why the `$` Sign is Displayed Instead of Hex Digits

In lines 78 to 82:
```assembly
78:     mov ah, 2
79:     mov dl, al
80:     int 21h
81:     
82:     mov bin_char, al     ; storing rotated value
```

Here, the program attempts to print `DL = AL` (the raw rotated binary value) as if it were an ASCII character.
Suppose the user entered the character `'2'`:
1. Character `'2'` has ASCII value `50` (`32h` = `0011 0010b`).
2. Line 48: `xor al, 32` gives $50 \oplus 32 = 18$ (`12h` = `0001 0010b`).
3. Line 75: `rol al, 1` rotates `0001 0010b` left by 1 bit $\rightarrow$ `0010 0100b` = $36$ (`24h`).
4. What character has ASCII code **`36` (`24h`)**?
   **`36` is precisely the ASCII character `'$'`!**
5. Line 79 loads `DL = 36` (`'$'`), and line 80 prints it to the console via DOS Service `02h`!

---

### Bug 3: Missing `add al, 48` in the `print` Procedure

Examine the `print` routine in [`8.1.asm#L114-L127`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-8_Labtest-1/8.1.asm#L114-L127):
```assembly
114: print proc
115:     cmp al, 57
116:     jbe print2
117:     
118:     add al, 7
119:     
120:     print2: 
121:     mov ah, 2
122:     mov dl, al
123:     int 21h
124:     
125:     ret
126:     
127:     print endp
```

1. Before calling `print`, `AL` holds an isolated nibble ($0$ to $15$).
2. Line 115 tests `cmp al, 57`.
3. Because $0 \le \text{AL} \le 15$, the condition $\text{AL} \le 57$ is **always true**.
4. The procedure branches to `print2:` every time, skipping `add al, 7`.
5. **The fundamental flaw**: `add al, 48` (or `add al, '0'`) is completely absent!
6. Line 121–123 sends raw values $0\text{h} \dots 0\text{Fh}$ to DOS Service `02h`. Values $0 \dots 15$ represent non-printable control characters (NUL, SOH, STX, etc.), producing **invisible glyphs** on the console.
7. Thus, the actual hex characters fail to appear, and only the erroneous `$` printed in step 2 remains visible.

### Bug 4: Phantom `INT 21h` Calls After ALU Operations

Lines 91–92 and 101–102 contain erroneous interrupt calls:
```assembly
91:     shr al, 4
92:     int 21h           ; <--- Completely invalid interrupt invocation!
93:    
94:     call print

101:    and al, 0Fh
102:    int 21h           ; <--- Completely invalid interrupt invocation!
103:     
104:    call print
```

- `SHR` and `AND` are CPU instructions; they do not invoke DOS.
- At line 92 and 102, `AH` still holds `02h` and `DL` still holds the last character printed (`'$'`). Invoking `int 21h` repeatedly prints `DL` again, multiplying the junk characters.

## 7. High-Level Language (C/C++) Equivalence

To bridge conceptual understanding, here is the exact equivalent C code:

```c
#include <stdio.h>

int main(void) {
    char ch;
    printf("Input = ");
    ch = getchar();

    // Invert case via XOR 32
    char converted = ch ^ 32;
    printf("\nConverted Character = %c\n", converted);

    // Rotate Left by 1 bit (8-bit unsigned circular shift)
    unsigned char val = (unsigned char)converted;
    unsigned char rotated = (val << 1) | (val >> 7);

    // Display Hexadecimal representation
    printf("Hex code after rotate left = ");
    
    // High nibble
    unsigned char high_nibble = (rotated >> 4) & 0x0F;
    char c1 = (high_nibble <= 9) ? (high_nibble + '0') : (high_nibble - 10 + 'A');
    putchar(c1);

    // Low nibble
    unsigned char low_nibble = rotated & 0x0F;
    char c2 = (low_nibble <= 9) ? (low_nibble + '0') : (low_nibble - 10 + 'A');
    putchar(c2);

    putchar('\n');
    return 0;
}
```

## 8. Key Takeaways and Debugging Checklist

1. **ALU Instructions Never Need `INT 21h`**: `ROL`, `ROR`, `SHL`, `SHR`, `AND`, `OR`, `XOR`, `ADD`, `SUB`, and `CMP` are purely internal CPU register operations. Calling `INT 21h` directly after them without reloading `AH` executes whatever previous service happened to remain in `AH`.
2. **Registers Retain Stale State**: If `AH = 09h` was used previously, calling `INT 21h` again will reuse `AH = 09h` with whatever address resides in `DX`.
3. **Converting Raw Values to Hex Requires Two Steps**:
   - Add $48$ (`'0'`).
   - If greater than $57$ (`'9'`), add $7$.
   - Forgetting `add al, 48` results in non-printable ASCII codes ($0\text{h} \dots 0\text{Fh}$).
4. **Inspect ASCII Characters for Bit Patterns**: If unexpected symbols like `'$'` (ASCII `36` = `24h`) appear on screen, check whether a numeric operation produced `24h` and was passed inadvertently to `INT 21h, AH=02h`.

## 9. Mathematical Analysis: ROL vs. SHR and the 'H' Suffix (`30H` vs. `C2H`)

When testing input `'A'`, the user noted an expected result of `30H`. Let us dissect the exact bit-level arithmetic:

### Input Character Trace:
1. **Input**: `'A'` = ASCII `41h` (`0100 0001b`).
2. **Case Conversion (`XOR AL, 32`)**:
   $$41\text{h} \oplus 20\text{h} = 61\text{h} = 97\text{d} = \text{'a'} \quad (\mathbf{0110\ 0001b})$$

### Operation A: Rotate Left by 1 (`ROL AL, 1`)
- Circularly shifting `0110 0001b` left by 1 bit:
  - Bit 7 (`0`) rotates to Bit 0 and Carry Flag (`CF`).
  - Remaining bits shift left:
  $$\mathbf{0110\ 0001b} \xrightarrow{\text{ROL 1}} \mathbf{1100\ 0010b} = \mathbf{C2h}$$
- High nibble: `1100b` = `12` $\rightarrow$ ASCII `'C'`.
- Low nibble: `0010b` = `2` $\rightarrow$ ASCII `'2'`.
- **Result of `ROL 1`**: `C2` (or `C2H`).

### Operation B: Logical Shift Right by 1 (`SHR AL, 1`)
- Shifting `0110 0001b` right by 1 bit (injecting `0` at Bit 7):
  $$\mathbf{0110\ 0001b} \xrightarrow{\text{SHR 1}} \mathbf{0011\ 0000b} = \mathbf{30h}$$
- High nibble: `0011b` = `3` $\rightarrow$ ASCII `'3'`.
- Low nibble: `0000b` = `0` $\rightarrow$ ASCII `'0'`.
- **Result of `SHR 1`**: `30` (or `30H`).

| Operation | Input `'A'` $\rightarrow$ `'a'` (`61h`) | High Nibble | Low Nibble | Formatted Output |
| :--- | :--- | :--- | :--- | :--- |
| **`ROL AL, 1`** (Rotate Left) | `0110 0001b` $\rightarrow$ `1100 0010b` | `'C'` | `'2'` | **`C2H`** |
| **`SHR AL, 1`** (Shift Right) | `0110 0001b` $\rightarrow$ `0011 0000b` | `'3'` | `'0'` | **`30H`** |

> [!IMPORTANT]
> If your lab assignment specifies that input `'A'` must produce `30H`, the required bitwise instruction is **`shr al, 1` (Shift Right by 1)** rather than `rol al, 1` (Rotate Left by 1).

### Printing the 'H' Suffix
To print the trailing `'H'` character after the two hex nibbles:
```assembly
    ; Print 'H' suffix
    mov dl, 'H'
    mov ah, 02h
    int 21h
```
