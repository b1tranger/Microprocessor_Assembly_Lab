# Multi-Digit Display Mechanics: Arithmetic Division (3.2.asm) vs. Bitwise Hex Extraction (5.1.asm)

When displaying numeric results on the console via DOS Interrupt `21h` (Service `02h`), the 8086 processor cannot simply print numbers directly; it can only print **ASCII character glyphs** (one byte at a time). When a numerical result spans two or more digits, those digits must first be mathematically or logically separated, then converted to ASCII.

This document examines and compares the two distinct paradigms for printing double digits in 8086 assembly:
1. **Arithmetic Separation (Base-10 / Decimal)** via `DIV 10` as seen in [`3.2.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm).
2. **Bitwise Separation (Base-16 / Hexadecimal)** via `SHR` and `AND` as seen in [`5.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-5_Bitwise_Hex_Display/5.1.asm).

## 1. Does AL Store Binary Values in Both Cases?

### The Short Answer
**Yes, absolutely.** At the hardware level, every register in the 8086 CPU (`AL`, `AH`, `BL`, etc.) and every memory cell in RAM stores **only binary bits (`0`s and `1`s)**. The CPU has no physical concept of decimal, hexadecimal, or ASCII characters—it only stores high and low electrical voltages across 8 flip-flops in the `AL` register.

### The Semantic Difference (What the Binary Bits Represent)
While both store binary voltages, **what those bits semantically represent** changes at each step:

```
[Phase 1: Raw Numeric Value]
   AL holds binary magnitude:
   - 3.2.asm: 0001 1100b (Decimal 28 product)
   - 5.1.asm: 1101 0001b (Hex 0D1h value)
             |
             v
[Phase 2: Separated Digits]
   AL holds binary representation of individual digits:
   - 3.2.asm: AL = 0000 0010b (2 tens), AH = 0000 1000b (8 units)
   - 5.1.asm: AL = 0000 1101b (Upper nibble D), AL = 0000 0001b (Lower nibble 1)
             |
             v
[Phase 3: ASCII Character Encoding]
   AL holds the binary ASCII code for the display monitor:
   - 3.2.asm: AL = 0011 0010b (ASCII '2' / 50d), AH = 0011 1000b (ASCII '8' / 56d)
   - 5.1.asm: AL = 0100 0100b (ASCII 'D' / 68d), AL = 0011 0001b (ASCII '1' / 49d)
```

## 2. Code Comparison: 5.1.asm vs. 3.2.asm

### Snippet A: [`5.1.asm#L25-L31`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-5_Bitwise_Hex_Display/5.1.asm#L25-L31) (Hexadecimal Display)

```assembly
mov al, bl 
shr al, 4          ; Extract upper 4-bit nibble
call print_hex     ; Print first hex character

mov al, bl
and al, 0Fh        ; Extract lower 4-bit nibble
call print_hex     ; Print second hex character
```

### Snippet B: [`3.2.asm#L50-L70`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm#L50-L70) (Decimal Display)

```assembly
mov al, num1
mul num2           ; AX = AL * num2 (raw product)
add al, 48         ; [Caution: Pre-mature conversion bug in lab file]
mov multi, al

; separating digits before output
mov al, multi
mov bl, 10
div bl             ; AL = AX / 10 (Quotient), AH = AX % 10 (Remainder)
add al, 48         ; Convert quotient (tens digit) to ASCII
add ah, 48         ; Convert remainder (units digit) to ASCII
mov quot, al
mov rem, ah     

mov ah, 2
mov dl, quot  
int 21h            ; Print tens digit
mov ah, 2
mov dl, rem  
int 21h            ; Print units digit
```

## 3. Deep Architectural Comparison: Base-10 vs. Base-16

Why do the two programs use completely different techniques to print two digits?

```
+-------------------------------------------------------------------------+
|                  WHY CAN'T WE USE SHR / AND FOR DECIMAL?                |
+-------------------------------------------------------------------------+
| Base-16 (Hexadecimal):                                                  |
| 16 = 2^4. Each hexadecimal digit matches EXACTLY 4 binary bits.         |
| 1 Byte = 8 bits = Exactly TWO 4-bit nibbles: [ Nibble 1 ] [ Nibble 0 ]  |
| Because digits align with powers of 2, bit shifts and masks work!       |
|                                                                         |
| Base-10 (Decimal):                                                      |
| 10 is NOT a power of 2 (2^3 = 8 < 10 < 2^4 = 16).                       |
| Decimal digits cross arbitrary fractional bit boundaries.               |
| For example, 28 = 0001 1100b.                                           |
| You cannot shift or mask 0001 1100b to get '2' and '8'.                 |
| You MUST perform arithmetic division by 10.                             |
+-------------------------------------------------------------------------+
```

## 4. Mechanics of Arithmetic Digit Separation (`DIV 10`) in `3.2.asm`

In decimal representation, any two-digit number $N \in [0, 99]$ is mathematically decomposed as:
$$N = (\text{Tens} \times 10) + \text{Units}$$

Where:
$$\text{Tens} = \lfloor N / 10 \rfloor = \text{Quotient}$$
$$\text{Units} = N \pmod{10} = \text{Remainder}$$

### Hardware Execution of `div bl` (where `bl = 10`):
- **Input**: The 16-bit register `AX`.
- **Operation**: `AX / 10`.
- **Outputs**:
  - `AL` receives the 8-bit integer **quotient** (Tens digit).
  - `AH` receives the 8-bit integer **remainder** (Units digit).

### Example Walkthrough ($N = 28$):
1. `AX = 001Ch` ($28$).
2. `DIV BL` (with `BL = 10`):
   - $\text{Quotient} = 28 / 10 = 2 \rightarrow \text{stored in } \mathbf{AL}$.
   - $\text{Remainder} = 28 \pmod{10} = 8 \rightarrow \text{stored in } \mathbf{AH}$.
3. Convert to ASCII:
   - `add al, 48` $\rightarrow 2 + 48 = 50$ (ASCII `'2'`).
   - `add ah, 48` $\rightarrow 8 + 48 = 56$ (ASCII `'8'`).
4. Print sequentially:
   - First `INT 21h / AH=02h` prints `'2'`.
   - Second `INT 21h / AH=02h` prints `'8'`.
   - Result displayed on console: **`28`**.

## 5. Mechanics of Bitwise Nibble Extraction (`SHR` / `AND`) in `5.1.asm`

An 8-bit register consists of two 4-bit nibbles:
$$\text{Register BL} = [b_7 b_6 b_5 b_4] \; [b_3 b_2 b_1 b_0]$$

Each 4-bit nibble has values from $0$ to $15$ (`0h` to `Fh`), corresponding directly to one hexadecimal digit.

### 1. Extracting the Upper Nibble (`SHR AL, 4`)
```
Initial AL:    [ 1  1  0  1 ] [ 0  0  0  1 ]  (0D1h)
SHR AL, 4:     [ 0  0  0  0 ] [ 1  1  0  1 ]  (0Dh = 13 decimal)
```
The upper 4 bits shift into the lower 4 bit positions; zeroes fill the top 4 bits. `AL` now holds the numeric value `13` (`'D'`).

### 2. Extracting the Lower Nibble (`AND AL, 0Fh`)
```
Initial AL:    [ 1  1  0  1 ] [ 0  0  0  1 ]  (0D1h)
Mask 0Fh:    & [ 0  0  0  0 ] [ 1  1  1  1 ]
Result AL:     [ 0  0  0  0 ] [ 0  0  0  1 ]  (01h = 1 decimal)
```
The `AND` mask zeroes out the upper 4 bits while preserving the lower 4 bits unchanged. `AL` now holds the numeric value `1`.

## 6. ASCII Conversion Differences (`+48` vs. `+48 / +7`)

| Metric | Decimal Digits ([`3.2.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm)) | Hexadecimal Digits ([`5.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-5_Bitwise_Hex_Display/5.1.asm)) |
| :--- | :--- | :--- |
| **Possible Values** | `0` through `9` | `0` through `15` (`0`–`9`, `A`–`F`) |
| **ASCII Output** | `'0'` through `'9'` (`30h`–`39h`) | `'0'`–`'9'` (`30h`–`39h`) and `'A'`–`'F'` (`41h`–`46h`) |
| **Conversion Formula** | Always `+ 48` | If $\le 9$: `+ 48`<br>If $> 9$: `+ 48 + 7` (`+ 55`) |
| **Branching Needed?** | **No** (Direct addition) | **Yes** (`CMP AL, 57` followed by `JBE`) |

In ASCII encoding, there is a gap of **7 non-alphanumeric characters** (`:`, `;`, `<`, `=`, `>`, `?`, `@`) between ASCII `'9'` (57) and ASCII `'A'` (65).
- For decimal, values never exceed 9, so the gap is never reached.
- For hexadecimal, values 10–15 must add an extra `7` ($58 + 7 = 65 = \text{'A'}$) to cross this ASCII gap.

## 7. Critical Bug Analysis in `3.2.asm` (Lines 52–53)

In [`3.2.asm#L50-L54`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm#L50-L54):

```assembly
50:     mov al, num1
51:     mul num2         ; AL = num1 * num2
52:     add al, 48       ; <-- BUG: Premature ASCII conversion!
53:     mov multi, al
54:     
55:     ; separating digits before output
56:     
57:     mov al, multi
58:     mov bl, 10
59:     div bl
```

### Why Line 52 is a Bug:
1. **Corrupts the Division Input**:
   - Suppose `num1 = 3` and `num2 = 4`. The product is $3 \times 4 = 12$.
   - Line 52 adds 48: $12 + 48 = 60$.
   - Line 59 divides 60 by 10: $60 / 10 = 6$, Remainder = $0$.
   - The program will output **`60`** instead of **`12`**!
2. **Fails to Clear `AH` Before `DIV`**:
   - `MUL num2` stores a 16-bit result in `AX` (`AL` = low byte, `AH` = high byte).
   - `DIV BL` divides the entire 16-bit word `AX` by `BL`.
   - If line 57 only restores `AL` (`mov al, multi`), `AH` still holds leftover bits from `MUL`, causing arithmetic corruption or a `Divide by Zero / Overflow` exception (`INT 0`).

### Correct Pattern Applied to [`3.2.asm#L50-L70`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm#L50-L70):
```assembly
    ; MUL    
    mov al, num1
    mul num2     ; AL is automatically multiplied by num2; result in AX (AL * num2)
    mov multi, al ; FIX: Store RAW binary product (do NOT add 48 here before division)
    
    ; separating digits before output
    mov al, multi
    mov ah, 0    ; FIX: Clear AH to ensure AX contains strictly the 16-bit dividend (00:multi)
    mov bl, 10
    div bl       ; AX / 10 -> AL = Quotient (tens digit), AH = Remainder (units digit)
    add al, 48   ; Convert tens digit to ASCII character code ('0'-'9')
    add ah, 48   ; Convert units digit to ASCII character code ('0'-'9')
    mov quot, al
    mov rem, ah     
    
    mov ah, 2
    mov dl, quot  
    int 21h      ; Print tens digit
    mov ah, 2
    mov dl, rem  
    int 21h      ; Print units digit
```

## 9. Program Termination Syntax: `4ch` vs. `4Ch` & `MOV` vs. `ADD`

In [`3.2.asm#L81-L83`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-3_Arithmetic_Operations/3.2.asm#L81-L83):

```assembly
    ; DOS program termination
    mov ah, 4Ch
    int 21h
```

### 1. Can You Write `4ch` Instead of `4Ch`?
**Yes, 100%. They are completely interchangeable.**

In 8086 assembly (MASM, TASM, emu8086), hexadecimal literals and suffixes are **strictly case-insensitive**:
- `4ch` == `4Ch` == `4CH` == `4cH`
- All of them represent the exact same numeric value: $4 \times 16 + 12 = 76$ decimal (`0100 1100b`).
- All of them compile to the exact same 2 bytes of machine opcode:
  ```
  B4 4C       ; B4 = MOV AH, imm8 ; 4C = 76d / 4Ch
  ```

| Variation | Hex Digit 'C' Case | 'h' Base Suffix Case | Assembler Handling | Machine Code Emitted |
| :--- | :--- | :--- | :--- | :--- |
| `mov ah, 4ch` | Lowercase | Lowercase | Valid | `B4 4C` |
| `mov ah, 4Ch` | Uppercase | Lowercase | Valid | `B4 4C` |
| `mov ah, 4CH` | Uppercase | Uppercase | Valid | `B4 4C` |
| `mov ah, 04Ch` | Uppercase (with leading 0) | Lowercase | Valid | `B4 4C` |

> [!TIP]
> Some developers prefer `4Ch` because the uppercase `C` distinguishes the hex digit from the trailing `h` base identifier. However, the assembler treats them identically.

---

### 2. Can You Use the `ADD` Instruction Instead of `MOV`?
**No. The instruction must be `MOV`, not `ADD`.**

If you literally meant the assembly instruction `add ah, 4Ch`:
```assembly
    add ah, 4Ch    ; DANGEROUS / BUG!
    int 21h
```
- `ADD` performs arithmetic addition: $\text{AH} = \text{AH} + 4\text{Ch}$.
- At line 82, `AH` holds whatever value was left by the previous operation (`int 21h` print service leaves return state, or previous arithmetic).
- Adding `4Ch` produces an arbitrary sum (e.g. $2 + 76 = 78 = 4\text{Eh}$).
- When `int 21h` executes with $\text{AH} \ne 4\text{Ch}$, DOS executes a completely different system call (or an invalid service), causing unexpected behavior rather than terminating the program.
- Therefore, **`MOV AH, 4Ch` (assignment)** is strictly required.
