## 1. Overview of Character I/O Services

MS-DOS provides standard low-level character stream services via software interrupt `INT 21h`:

| Service (`AH`) | Operation Name | Input Parameters | Output / Return Values | Echo to Screen? |
|---|---|---|---|---|
| **`01h`** | Keyboard Character Input | None | **`AL` = ASCII code of key** | **Yes** (Automatic) |
| **`02h`** | Display Single Character | **`DL` = ASCII code to print** | `AL` = Last character printed | N/A |
| **`08h`** | Character Input without Echo | None | `AL` = ASCII code of key | No |
| **`09h`** | Display String | `DS:DX` = Address of `$`-string | None | N/A |

## 2. Analysis of Input Block: `2.1.asm:L8-L10` (`MOV AH, 1` / `INT 21h` / `MOV BL, AL`)

Referencing [`2.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-2_Character_IO/2.1.asm):

```assembly
mov ah, 1
int 21h
mov bl, al
```

### Why `2.1.asm:L8-L10` is Completely Valid

**YES, this code block is 100% VALID, standard, and represents the canonical pattern for reading a character from the keyboard in 8086 MS-DOS assembly.**

Each instruction performs a necessary architectural function:

```
[ Line 8: MOV AH, 1 ]    ---> Sets Function Code 01h in upper accumulator byte AH
                                (Tells DOS: "Prepare to read one key with echo")
                                
[ Line 9: INT 21h ]      ---> EXECUTE SYSCALL!
                                1. Pauses program execution.
                                2. Waits until a key is pressed on the keyboard.
                                3. Automatically displays (echoes) that key on the screen.
                                4. Places the 8-bit ASCII value into AL register.
                                
[ Line 10: MOV BL, AL ]  ---> PRESERVATION!
                                Copies the ASCII byte from AL into BL.
```

### Hardware & OS Behavior During Service `01h`

1. **Blocking Wait**: When `INT 21h` executes with `AH = 01h`, the CPU enters a polling/idle state waiting for a keystroke in the BIOS keyboard buffer (memory address `0040:001Eh`).
2. **Keystroke Processing**: Once a key is pressed, DOS reads the scan code and converts it to its 8-bit ASCII equivalent.
3. **Screen Echo**: DOS automatically writes that ASCII character to the video display buffer at the current cursor position and advances the cursor by 1 column.
4. **Deposit into `AL`**: DOS leaves the ASCII byte directly in register **`AL`** before executing `IRET` to return control to your program.

### Why `MOV BL, AL` is Essential (Accumulator Volatility)

Why not just leave the character in `AL`?
* **`AX` is the primary CPU accumulator**, composed of `AH` (bits 8–15) and `AL` (bits 0–7).
* Almost every subsequent operation modifies `AX`:
  - Preparing to print another character requires: `MOV AH, 2` (which shares the same 16-bit physical register `AX`).
  - Arithmetic operations (`MUL`, `DIV`, `CBW`) automatically overwrite `AL` and `AH`.
  - Exiting the program requires `MOV AH, 4Ch`, immediately destroying whatever was in `AH`.
* If you do not immediately preserve the value of `AL` into a non-volatile general-purpose register such as **`BL`** (or push it onto the stack / store it in RAM), **the character read from the user will be permanently clobbered and lost** on the very next instruction that modifies `AX` or calls DOS.

## 3. DOS Service `02h`: Single Character Output Contract

### Register Specification for Service `02h`

To display a character on the standard output device (console screen), MS-DOS defines a strict API calling convention:

1. **`AH = 02h`**: Specifies that the DOS dispatcher should route the call to the console output routine.
2. **`DL = Character`**: Specifies the 8-bit ASCII value of the character to be printed.
3. **`INT 21h`**: Fires the software interrupt to execute the display.

```
       [ Application ]                     [ 8086 CPU ]                       [ DOS Kernel ]
  1. MOV AH, 02h             --->       AH = 02h
  2. MOV DL, 'A' (41h)       --->       DL = 41h
  3. INT 21h                 --->       Traps to IVT [0084h]  --->    Reads DL, outputs 'A' to screen
```

### The Canonical Execution Pattern

Because the CPU executes instructions in linear sequence, **parameters MUST be loaded into their respective registers before triggering `INT 21h`**.

## 4. Analysis of Output Block: `2.2.asm:L14-L16` (The Correct Pattern)

In [`2.2.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-2_Character_IO/2.2.asm):

```assembly
mov ah, 2
mov dl, 32 ; printing a space 
int 21h
```

### Evaluation: **VALID (Proper and Correct)**
* **Line 14 (`mov ah, 2`)**: Selects DOS Service `02h` (Character Output).
* **Line 15 (`mov dl, 32`)**: Correctly stages the input character into `DL` (ASCII `32` = Space `' '`).
* **Line 16 (`int 21h`)**: Triggers the interrupt. The DOS routine reads `DL` ($32$) and renders exactly one blank space on the screen.

## 5. Analysis of Output Block: `2.1.asm:L12-L16` (The Premature Trigger Bug)

In [`2.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-2_Character_IO/2.1.asm):

```assembly
mov ah, 2
int 21h
mov dl, bl
int 21h
```

### Evaluation: **INVALID / FLAWED (Contains a Premature Interrupt Bug)**

This block contains a logic error: **`INT 21h` is called twice, and the first call occurs before `DL` has been initialized with the character to print!**

### Step-by-Step CPU Trace of `2.1.asm:L12-L16`

1. **Line 12**:
   ```assembly
   mov ah, 2      ; AH = 02h (Character output function selected).
   ```
2. **Line 13**:
   ```assembly
   int 21h        ; ⚠️ FIRST INTERRUPT FIRED PREMATURELY!
   ```
   - **`DL` was NEVER assigned any character!** 
   - Whatever residual data, uninitialized memory, or garbage was left in `DL` from startup or previous instructions will be sent to the screen.
   - Result: An unintended garbage character, null byte, or random ASCII symbol is displayed on the screen.
3. **Line 14**:
   ```assembly
   mov dl, bl     ; Now DL is finally loaded with the character stored in BL.
   ```
4. **Line 15**:
   ```assembly
   int 21h        ; Second interrupt fired. Now it prints the value in BL.
   ```

### Why It Produces an Accidental Double Print

Instead of printing just the value stored in `BL`, this block prints **two characters**:
1. **First output**: Garbage / uninitialized symbol from the uninitialized `DL`.
2. **Second output**: The intended character from `BL`.

## 6. Comparative Summary Table: Input vs. Output Services

| Operation | Service Code (`AH`) | Data Register Used | Timing / Staging Requirement | Example |
|---|---|---|---|---|
| **Character Read** | `AH = 01h` | **`AL` (Receives input)** | Read from `AL` **after** `INT 21h` | `MOV AH, 1` <br> `INT 21h` <br> `MOV BL, AL` |
| **Character Print** | `AH = 02h` | **`DL` (Provides output)** | Write to `DL` **before** `INT 21h` | `MOV AH, 2` <br> `MOV DL, BL` <br> `INT 21h` |

## 7. Best Practice Refactoring for `2.1.asm`

Here is the complete, corrected code for [`2.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-2_Character_IO/2.1.asm):

```assembly
.model small
.stack 100h

.code
main proc
    
    ; 1. Read character from keyboard with echo -> stores in AL
    mov ah, 1
    int 21h
    mov bl, al      ; Safely store input in BL before AX gets clobbered
    
    ; 2. Print the character stored in BL
    mov ah, 2       ; Service 02h: Print character
    mov dl, bl      ; Stage the character into DL BEFORE firing int 21h
    int 21h         ; Fire interrupt once!
    
exit:
    mov ah, 4ch     ; Service 4Ch: Terminate process
    int 21h
main endp
end main
```

## 8. Summary & Key Takeaways

1. **`2.1.asm:L8-L10` is completely valid**:
   - `MOV AH, 1` prepares keyboard read.
   - `INT 21h` pauses for keypress and deposits ASCII into `AL`.
   - `MOV BL, AL` protects the data against future accumulator corruption.
2. **Directionality of Registers**:
   - For **Input (`AH = 01h`)**: Data comes **OUT** of `AL` *after* the interrupt.
   - For **Output (`AH = 02h`)**: Data goes **INTO** `DL` *before* the interrupt.
3. **Preserving Accumulator State**: Always move values out of `AL` into registers like `BL`, `CL`, or memory if you need them across subsequent DOS calls.
