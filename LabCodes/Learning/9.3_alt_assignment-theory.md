# Nested Conditional Decision Trees, Equivalence Traps, and Multi-Branch Control Flow (9.3_alt_assignment.asm)

When extending two-variable comparison logic to three or more variables, assembly programmers often construct nested conditional decision trees. However, naive branching introduces subtle logical fallacies—particularly the **"Partial Equality" trap**, where early equality checks falsely short-circuit the comparison before all candidates are examined. This document analyzes [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm) (and its duplicate [`9.3_alt-2_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt-2_assignment.asm)), examining branch graph design, string formatting optimizations, critical logic flaws, and robust algorithms for handling ties and extrema.

## 1. Architectural Overview & Program Purpose

The program [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm) reads three user-supplied single-digit ASCII numbers into memory variables:
- `n1` ($A$)
- `n2` ($B$)
- `n3` ($C$)

It attempts to determine which variable is the largest among the three and report either:
- `" A is largest!"`
- `" B is largest!"`
- `" C is largest!"`
- `" Equal values!"`

While it improves on earlier implementations by embedding formatting bytes directly into data buffers, its comparison branching suffers from a severe structural flaw when handling duplicate values.

## 2. Data Organization & String Formatting Optimization

### Embedded CR/LF (`10, 13`) vs. Explicit Interrupt Calls

In [`9.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.1.asm#L28-L33), printing a newline required separate instructions and two distinct `INT 21h` invocations:
```assembly
; Inefficient newline generation:
mov ah, 2
mov dl, 10
int 21h
mov dl, 13
int 21h
```

[`9.3_alt_assignment.asm#L7-L15`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L7-L15) replaces this with **embedded control characters**:
```assembly
b_input db 10, 13, 'Enter the value of B: $'
c_input db 10, 13, 'Enter the value of C: $'
a       db 10, 13, ' A is largest!$'
b       db 10, 13, ' B is largest!$'
c       db 10, 13, ' C is largest!$'
equal   db 10, 13, ' Equal values!$'
```

* **Byte 10 (`0Ah`)**: Line Feed (moves cursor down to next row).
* **Byte 13 (`0Dh`)**: Carriage Return (moves cursor to leftmost column).
* **Performance Gain**: Embedding `10, 13` directly into string buffers eliminates 6 CPU instructions and 2 software interrupts per line break, drastically reducing code footprint and CPU cycles.

## 3. Decision Tree Analysis of `9.3_alt_assignment.asm`

### Branch Routing Architecture

The comparison logic begins at line 49 ([`9.3_alt_assignment.asm#L49-L54`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L49-L54)):
```assembly
mov al, n1
mov ah, n2
cmp al, ah
jg  a_is_big          ; If n1 > n2
jl  b_is_big          ; If n1 < n2
je  both_are_equal    ; If n1 == n2
```

Then branches route into sub-evaluations:
1. **Under `a_is_big`** ([`#L59-L65`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L59-L65)):
   - Compares `n1` with `n3`.
   - `jg a_is_big2` $\rightarrow$ Prints `A is largest!`
   - `jl c_is_big` $\rightarrow$ Prints `C is largest!`
   - `je both_are_equal2` $\rightarrow$ Prints `Equal values!`
2. **Under `b_is_big`** ([`#L70-L76`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L70-L76)):
   - Compares `n2` with `n3`.
   - `jg b_is_big2` $\rightarrow$ Prints `B is largest!`
   - `jl c_is_big` $\rightarrow$ Prints `C is largest!`
   - `je both_are_equal` $\rightarrow$ Prints `Equal values!`

### Visualizing the Control Flow Graph


## 4. The "Partial Equality" Fallacy (Critical Bug Analysis)

### The Premature Short-Circuit Trap ($A == B$)

Look closely at line 54 ([`9.3_alt_assignment.asm#L54`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L54)):
```assembly
mov al, n1
mov ah, n2
cmp al, ah
...
je both_are_equal
```

> [!CAUTION]
> **Critical Logic Bug**:
> If $n1 == n2$, the code jumps immediately to `both_are_equal` and terminates.
> **It never evaluates `n3`!**
> 
> Equality between $A$ and $B$ does **not** mean all values are equal, nor does it mean $C$ cannot be larger than both of them!

### Counterexample 1: $A=3, B=3, C=9$ (False Equality Detection)
1. User enters: $A = 3$, $B = 3$, $C = 9$.
2. CPU compares `n1` (`3`) and `n2` (`3`).
3. $3 - 3 = 0 \implies \text{ZF} = 1$.
4. `je both_are_equal` evaluates to TRUE.
5. CPU jumps directly to line 85 and outputs:
   ```
   Equal values!
   ```
6. **Failure**: The true maximum is $9$ ($C$), but $C$ was never even checked! The program outputs completely misleading information.

### Counterexample 2: $A=5, B=2, C=5$ (Tied Maximum Fallacy)
1. User enters: $A = 5$, $B = 2$, $C = 5$.
2. `n1 > n2` ($5 > 2$) evaluates to TRUE $\rightarrow$ branches to `a_is_big`.
3. In `a_is_big`, CPU compares `n1` (`5`) and `n3` (`5`).
4. $5 - 5 = 0 \implies \text{ZF} = 1$.
5. Line 65 (`je both_are_equal2`) branches to `both_are_equal2`.
6. Output:
   ```
   Equal values!
   ```
7. **Failure**: The values are not all equal ($B = 2$). The correct outcome is that $5$ is the maximum (tied between $A$ and $C$).

### True Mathematical Equality Condition ($A == B \land B == C$)

Three variables are equal if and only if **both** equality relations hold simultaneously:
$$(A == B) \land (B == C)$$
Checking only $A == B$ tests only 1 pair out of the 3 numbers.

## 5. The Missing `INT 21h` Termination Defect

In [`9.3_alt_assignment.asm#L112-L114`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L112-L114):
```assembly
exit:
    mov ah, 4ch

main endp
end main
```
As in earlier lab files, `int 21h` is omitted after loading `AH = 4Ch`.
The CPU will fall through the end of the code segment instead of returning control to DOS.

## 6. Comparative Evaluation: Alternative Decision Strategies

### Strategy 1: Full Permutational Tree (Strict Branching)
Requires explicitly handling cases where $A == B$, $B == C$, or $A == C$, creating up to 8 distinct branch paths. While correct, it requires many labels and conditional jumps.

### Strategy 2: The Running Maximum / Candidate Filter (Optimal)
Instead of a sprawling decision tree, assume the first number is the maximum candidate, then iteratively update the candidate if any subsequent number is strictly greater:

```
Candidate = A
If B > Candidate Then Candidate = B
If C > Candidate Then Candidate = C
Return Candidate
```

**Advantages of the Running Maximum approach**:
- Requires **only 2 comparisons total**, regardless of values.
- Completely immune to equality branching bugs: if $A == B$, the candidate remains $A$, which is mathematically correct!
- Scales cleanly to $N$ numbers using loops without exponential branch explosion.

## 7. High-Level Language (C/C++) Equivalence

```c
#include <stdio.h>

int main() {
    char a, b, c;

    printf("Enter the value of A: ");
    a = getchar(); getchar();
    printf("Enter the value of B: ");
    b = getchar(); getchar();
    printf("Enter the value of C: ");
    c = getchar();

    // Check complete equality first
    if (a == b && b == c) {
        printf("\n Equal values!\n");
    } else {
        // Determine strictly largest
        char max_val = a;
        char max_char = 'A';

        if (b > max_val) {
            max_val = b;
            max_char = 'B';
        }
        if (c > max_val) {
            max_val = c;
            max_char = 'C';
        }

        printf("\n %c is largest!\n", max_char);
    }

    return 0;
}
```

## 8. Corrected, Robust Assembly Implementation

Below is a robust implementation that properly verifies triple equality ($A == B == C$) and accurately identifies the largest value without getting trapped by partial duplicates:

```assembly
.model small
.stack 100h

.data
    a_input db 'Enter the value of A: $'
    b_input db 10, 13, 'Enter the value of B: $'
    c_input db 10, 13, 'Enter the value of C: $'

    msg_a   db 10, 13, ' A is largest!$'
    msg_b   db 10, 13, ' B is largest!$'
    msg_c   db 10, 13, ' C is largest!$'
    msg_eq  db 10, 13, ' All values are equal!$'

    n1 db ?
    n2 db ?
    n3 db ?

.code
main proc
    mov ax, @data
    mov ds, ax

    ; Read A
    mov ah, 9
    lea dx, a_input
    int 21h
    mov ah, 1
    int 21h
    mov n1, al

    ; Read B
    mov ah, 9
    lea dx, b_input
    int 21h
    mov ah, 1
    int 21h
    mov n2, al

    ; Read C
    mov ah, 9
    lea dx, c_input
    int 21h
    mov ah, 1
    int 21h
    mov n3, al

    ; --- Step 1: Check if ALL THREE are equal ---
    mov al, n1
    cmp al, n2
    jne find_largest        ; If A != B, they cannot all be equal
    cmp al, n3
    jne find_largest        ; If A != C, they cannot all be equal

    ; If both tests passed, A == B == C
    lea dx, msg_eq
    jmp display_result

find_largest:
    ; --- Step 2: Compare A against B ---
    mov al, n1
    mov bl, n2
    cmp al, bl
    ja  a_candidates        ; If A > B, candidate is A
    ; Otherwise B >= A, candidate is B
    mov al, bl              ; AL holds candidate (B)
    mov cl, n3
    cmp al, cl
    jae b_is_max            ; If B >= C, B is largest
    jmp c_is_max            ; Otherwise C is largest

a_candidates:
    ; Candidate is A, compare with C
    mov cl, n3
    cmp al, cl
    jae a_is_max            ; If A >= C, A is largest
    jmp c_is_max            ; Otherwise C is largest

a_is_max:
    lea dx, msg_a
    jmp display_result

b_is_max:
    lea dx, msg_b
    jmp display_result

c_is_max:
    lea dx, msg_c

display_result:
    mov ah, 9
    int 21h

    ; Clean Program Termination
    mov ah, 4ch
    int 21h

main endp
end main
```
