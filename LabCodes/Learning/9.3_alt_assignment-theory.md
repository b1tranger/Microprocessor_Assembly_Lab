# Nested Conditional Decision Trees, Equivalence Traps, and Multi-Branch Control Flow (9.3_alt_assignment.asm)

When extending two-variable comparison logic to three or more variables, assembly programmers often construct nested conditional decision trees. However, handling equality and duplicate values requires strict symmetry and careful branch routing to avoid false conclusions. This document analyzes the updated [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm) (and its companion [`9.3_alt-2_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt-2_assignment.asm)), examining branch graph design, string formatting optimizations, the mechanics of routing equal candidates (`je b_is_big`), the remaining edge-case asymmetry in `a_is_big`, and robust algorithms for handling ties and extrema.

## 1. Architectural Overview & Program Purpose

The program [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm) reads three single-digit ASCII numbers into memory variables:
- `n1` ($A$)
- `n2` ($B$)
- `n3` ($C$)

It determines which variable is the largest among the three and reports either:
- `" A is largest!"`
- `" B is largest!"`
- `" C is largest!"`
- `" Equal values!"`

The code features an important structural update at line 54:
```assembly
je b_is_big ; in case of equal case we can compare any one with the 3rd
```
This routes the equality condition between $A$ and $B$ directly into the second-stage comparison instead of short-circuiting prematurely.

## 2. Data Organization & String Formatting Optimization

### Embedded CR/LF (`10, 13`) vs. Explicit Interrupt Calls

In [`9.1.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.1.asm#L28-L33), printing a newline required separate instructions and two distinct `INT 21h` invocations:
```assembly
; Inefficient newline generation:
mov ah, 2
mov dl, 10
int 21h
mov dl, 13
int 21h
```

[`9.3_alt_assignment.asm#L7-L15`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L7-L15) replaces this with **embedded control characters**:
```assembly
b_input db 10, 13, 'Enter the value of B: $'
c_input db 10, 13, 'Enter the value of C: $'
a       db 10, 13, ' A is largest!$'
b       db 10, 13, ' B is largest!$'
c       db 10, 13, ' C is largest!$'
equal   db 10, 13, ' Equal values!$'
```

* **Byte 10 (`0Ah`)**: Line Feed (advances cursor down to the next display row).
* **Byte 13 (`0Dh`)**: Carriage Return (moves cursor back to column 0).
* **Performance Gain**: Embedding `10, 13` directly into string buffers eliminates 6 CPU instructions and 2 software interrupts per line break, drastically reducing code footprint and CPU cycles.

## 3. Decision Tree Analysis of Updated `9.3_alt_assignment.asm`

### Initial Comparison Branching (`CMP n1, n2`)

The initial comparison logic begins at lines 49–54 ([`9.3_alt_assignment.asm#L49-L54`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L49-L54)):
```assembly
mov al, n1
mov ah, n2
cmp al, ah
jg  a_is_big  ; if bl bigger than bh then jg flag on
jl  b_is_big  ; if bh bigger than bl then jl flag on
je  b_is_big  ; in case of equal case we can compare any one with the 3rd
```

### Sub-Branch Evaluations (`a_is_big` and `b_is_big`)

1. **Under `a_is_big`** ([`#L56-L66`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L56-L66)):
   - Reached when $n1 > n2$.
   - Compares `n1` ($A$) with `n3` ($C$).
   - `jg a_is_big2` $\rightarrow$ Outputs `" A is largest!"`.
   - `jl c_is_big` $\rightarrow$ Outputs `" C is largest!"`.
   - `je both_are_equal2` $\rightarrow$ Outputs `" Equal values!"`.
2. **Under `b_is_big`** ([`#L68-L77`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L68-L77)):

## 4. Deep Dive: The `je b_is_big` Tournament Routing Strategy

### Why Routing $A == B$ to $B$ Works

In tournament-style selection:
- If $A == B$, both values share the exact same numeric magnitude.
- Therefore, either one of them can serve as the candidate champion to face $C$.
- By routing `je` into `b_is_big`, the algorithm uses $B$ as the representative for $\{A, B\}$ and tests $B$ against $C$:
  1. **If $B > C$**: Since $B == A$, then both $A$ and $B$ are greater than $C$. Declaring $B$ as largest is mathematically correct.
  2. **If $B < C$**: Then $C$ is strictly greater than $B$ (and therefore also strictly greater than $A$). Declaring $C$ as largest is mathematically correct.
  3. **If $B == C$**: Since we entered `b_is_big` via $A == B$, and now find $B == C$, it logically follows by transitivity that:
     $$A == B == C$$
     Declaring `" Equal values!"` via `both_are_equal` is completely sound!

### Resolution of the $A=3, B=3, C=9$ Trap

In earlier implementations where `je` jumped straight to `both_are_equal`, input $A=3, B=3, C=9$ caused an immediate premature exit outputting `" Equal values!"`.

Under the updated code:
1. `n1 = '3'`, `n2 = '3'`, `n3 = '9'`.
2. `cmp al, ah` evaluates $3 - 3 = 0 \implies \text{ZF} = 1$.
3. Line 54 (`je b_is_big`) triggers, jumping to `b_is_big`.
4. Inside `b_is_big`, CPU compares `n2` (`3`) with `n3` (`9`):
   $$3 - 9 = -6 \implies \text{SF} = 1, \text{OF} = 0 \implies \text{SF} \ne \text{OF}$$
5. Line 75 (`jl c_is_big`) triggers!
6. Output:
   ```
   C is largest!
   ```
The user's update **completely resolves this bug**.

### Resolution of the Triple-Equality Case ($A = B = C$)

Consider input $A=7, B=7, C=7$:
1. `cmp al, ah` evaluates $7 - 7 = 0 \implies \text{ZF} = 1 \implies$ jumps to `b_is_big`.
2. Inside `b_is_big`, `cmp al, ah` evaluates $7 - 7 = 0 \implies \text{ZF} = 1$.
3. Line 76 (`je both_are_equal`) triggers!
4. Output:
   ```
   Equal values!
   ```
All three values are correctly recognized as equal.

### Instruction Optimization: Collapsing `JL` + `JE` into `JLE`

Notice lines 53–54:
```assembly
jl  b_is_big
je  b_is_big
```
In 8086 machine code, testing both "Less Than" and "Equal To" against the same destination can be collapsed into a single instruction:
```assembly
jle b_is_big          ; Jump if Less or Equal (ZF = 1 OR SF != OF)
```
Or, by using inverted flow:
```assembly
cmp al, ah
jg  a_is_big          ; If A > B, handle A
jmp b_is_big          ; Otherwise (B >= A), handle B
```
This saves 2 bytes of code and reduces branch decoding overhead.

## 5. The Remaining Edge-Case: Asymmetry in `a_is_big` ($A == C > B$)

While the user's update elegantly fixed the $A == B$ path, examine the symmetry of the complementary branch: what happens inside `a_is_big` when $A == C$?

### The Tied-Maximum Trap: $A=5, B=2, C=5$

Consider inputs: $A = 5, B = 2, C = 5$.
1. Initial comparison: `n1` ($5$) vs `n2` ($2$).
2. $5 > 2 \implies$ line 52 (`jg a_is_big`) triggers.
3. CPU enters `a_is_big` ([`#L56-L65`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L56-L65)):
   ```assembly
   mov al, n1         ; AL = 5
   mov ah, n3         ; AH = 5
   cmp al, ah         ; 5 - 5 = 0 -> ZF = 1
   jg  a_is_big2
   jl  c_is_big
   je  both_are_equal2 ; Jumps here!
   ```
4. Target `both_are_equal2` ([`#L104-L109`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L104-L109)) outputs:
   ```
   Equal values!
   ```

### Why `both_are_equal2` Triggers Falsely

> [!WARNING]
> In `a_is_big`, the CPU only arrives because $A > B$ was **already proven strictly true**!
> 
> Therefore, if $A == C$, the values are:
> $$A = 5, \quad C = 5, \quad B = 2 \implies A = C > B$$
> The three numbers are **not** all equal! In fact, $5$ is the maximum value (shared by $A$ and $C$), while $B$ is smaller. Calling this `"Equal values!"` is misleading because $B$ is unequal.

### How to Restore Full Symmetrical Robustness

To make `a_is_big` as robust as `b_is_big`:
- If $A > B$ and $A == C$, then $A$ (and $C$) is the maximum!
- Instead of jumping to `both_are_equal2`, jump to `a_is_big2` (or use `jge a_is_big2`):

```assembly
a_is_big:
    mov al, n1
    mov ah, n3
    cmp al, ah
    jge a_is_big2       ; If A >= C, A is largest!
    jmp c_is_big        ; Otherwise C > A, so C is largest!
```

## 6. The Missing `INT 21h` Termination Defect

In lines 112–114 of [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L112-L114):
```assembly
exit:
    mov ah, 4ch

main endp
end main
```

> [!CAUTION]
> **Program Termination Trap**:
> `mov ah, 4ch` loads the DOS service request number into `AH`, but **never triggers the interrupt**.
> Without `int 21h`, MS-DOS does not regain control. The processor will continue incrementing `IP` past the end of the code segment, causing erratic execution or emulator hangs.

**Correction**:
```assembly
exit:
    mov ah, 4ch
    int 21h           ; Crucial: Hands execution back to MS-DOS
```

## 7. Comparative Evaluation: Alternative Decision Strategies

### Strategy 1: Full Permutational Tree (Strict Branching)
The updated `9.3_alt_assignment.asm` implements this approach. When both `a_is_big` and `b_is_big` are made symmetrical, it cleanly partitions cases in 2 comparisons per run.

### Strategy 2: The Running Maximum / Candidate Filter (Optimal)
Instead of multi-way branch routing, maintain a single candidate in register `AL`:
```assembly
    mov al, n1          ; Candidate = A
    cmp n2, al
    jbe check_c         ; If B <= Candidate, keep A
    mov al, n2          ; Candidate = B
check_c:
    cmp n3, al
    jbe done            ; If C <= Candidate, keep current
    mov al, n3          ; Candidate = C
done:
    ; AL holds the true maximum value regardless of equality!
```

            printf("\n C is largest!\n");
        } else {
            // Under both_are_equal (triggered if n1 == n2 == n3 OR n2 == n3 > n1)
            printf("\n Equal values!\n");
        }
    }

## 9. Fully Symmetrical and Robust Assembly Implementation

Below is the refined version integrating the user's `je b_is_big` insight, harmonizing the `a_is_big` branch for full symmetry, and ensuring clean program termination:

```assembly
.model small
.stack 100h

.data
    a_input db 'Enter the value of A: $'
    b_input db 10, 13, 'Enter the value of B: $'
    c_input db 10, 13, 'Enter the value of C: $'

    msg_a   db 10, 13, ' A is largest!$'
    msg_b   db 10, 13, ' B is largest!$' 
    msg_c   db 10, 13, ' C is largest!$'
    msg_eq  db 10, 13, ' All values are equal!$'

    n1 db ?
    n2 db ? 
    n3 db ?

.code
main proc
    mov ax, @data
    mov ds, ax

    ; Read A
    mov ah, 9
    lea dx, a_input
    int 21h
    mov ah, 1
    int 21h
    mov n1, al

    ; Read B
    mov ah, 9
    lea dx, b_input
    int 21h
    mov ah, 1
    int 21h
    mov n2, al

    ; Read C
    mov ah, 9
    lea dx, c_input
    int 21h
    mov ah, 1
    int 21h
    mov n3, al

    ; --- Step 1: Check True Global Equality (A == B == C) ---
    mov al, n1
    cmp al, n2
    jne compare_tournament  ; If A != B, not all are equal
    cmp al, n3
    jne compare_tournament  ; If A != C, not all are equal

    ; All three numbers are identical
    lea dx, msg_eq
    jmp print_and_exit

compare_tournament:
    ; --- Step 2: Tournament Comparison ---
    mov al, n1
    mov ah, n2
    cmp al, ah
    jg  a_candidates        ; If A > B, candidate is A
    jle b_candidates        ; If B >= A, candidate is B (User's insight)

a_candidates:
    mov al, n1
    mov ah, n3
    cmp al, ah
    jge a_is_largest        ; If A >= C, A is largest!
    jmp c_is_largest        ; Otherwise C > A, C is largest!

b_candidates:
    mov al, n2
    mov ah, n3
    cmp al, ah
    jge b_is_largest        ; If B >= C, B is largest!
    jmp c_is_largest        ; Otherwise C > B, C is largest!

a_is_largest:
    lea dx, msg_a
    jmp print_and_exit

b_is_largest:
    lea dx, msg_b
    jmp print_and_exit

c_is_largest:
    lea dx, msg_c

print_and_exit:
    mov ah, 9
    int 21h

exit:
    mov ah, 4ch
    int 21h                 ; Proper DOS termination

main endp
end main
```
