# Procedures, Labels, and Control Flow in 8086 Assembly (5.1.asm)

In 8086 assembly programming, structuring code and controlling the flow of execution involves two fundamental concepts: **Subroutines (Procedures)** and **Branching (Jumps)**. This document explains the differences between `PROC` directives, plain labels, `CALL`/`RET` mechanics, and conditional jumps (`JMP`, `JBE`, etc.), using the hexadecimal printing routine in `5.1.asm` as a practical example.

## 1. Procedures (`PROC` / `ENDP`) vs. Plain Labels (`label:`)


### What is a Procedure?
A procedure (subroutine) in 8086 assembly is defined using the `PROC` and `ENDP` directives:

```assembly
print_hex PROC
    ; Procedure body
    ret
print_hex ENDP
```

- **`PROC` and `ENDP` are Assembler Directives**: They are instructions for the assembler (MASM, TASM, emu8086), not actual CPU machine instructions.
- **Memory Model / Return Type Handling**: When you define a procedure, the assembler determines whether it is `NEAR` (within the same code segment) or `FAR` (across different segments). When it encounters `RET`, it automatically generates either a near return (`RETN`, popping 2 bytes for `IP`) or a far return (`RETF`, popping 4 bytes for `IP` and `CS`).
- **Scope & Readability**: They delineate clear modular boundaries for subroutines in your code.

### What is a Plain Label?
A label is simply a symbolic name marking a specific memory offset in the code segment:

```assembly
print_hex:
    ; Routine body
    ret
```

- **Address Marker**: `print_hex:` simply tells the assembler: *"Remember this memory address by the name `print_hex`."*

### Can You Call a Plain Label (`call print_hex:`)?
**Yes.** In 8086 assembly, the CPU's `CALL` instruction only requires an address (offset). Even if defined with a plain label, `CALL print_hex` will push the Instruction Pointer (`IP`) onto the stack and jump to that label. When the CPU reaches `RET`, it will pop `IP` off the stack and return.

> [!NOTE]
> While a plain label works with `CALL` in a `SMALL` memory model, using `PROC ... ENDP` is the standard practice because it prevents segment return bugs and makes the code modular and maintainable.

## 2. `CALL` / `RET` (Functions) vs. `JMP` / Conditional Jumps (Branching)

A common misconception is treating branch labels (like `out:`) as user-defined functions called with jump instructions (`jbe`, `jmp`).

### How `CALL` and `RET` Work (Subroutine Calls)
1. **`CALL target`**:
   - The CPU automatically pushes the address of the *next* instruction (the return address in `IP`) onto the Stack.
   - It sets `IP` to the address of `target`.
2. **`RET`**:
   - The CPU pops the top 16-bit value from the Stack into `IP`.
   - Execution resumes seamlessly right after the original `CALL` instruction.

```
Caller Code               Procedure (print_hex)
+-------------------+      +-------------------+
| mov al, bl        |      | add al, 48        |
| call print_hex ---+----->| ...               |
| [Next Inst.] <----+------+--- ret            | (Pops return address)
+-------------------+      +-------------------+
 (Stack saves IP)
```

---

### How `JMP` and Conditional Jumps (`JBE`, `JE`, `JNE`, etc.) Work (Branching)
- **Direct Control Transfer**: Jumps do **not** interact with the Stack. They do not store a return address.
- **One-Way Execution**: A jump simply overwrites `IP` with the target label's address. There is no `RET` mechanism to return back automatically.
- **Purpose**: Used to implement conditionals (`if-else`), loops (`while`, `for`), and multi-way branching.

---

### Comparison Summary

| Feature | `CALL` / `RET` (Procedure / Subroutine) | `JMP` / Conditional Jumps (`JBE`, `JE`, etc.) |
| :--- | :--- | :--- |
| **Stack Usage** | **Pushes** return address (`IP`) to Stack. | **No stack modification**. |
| **Return Mechanism** | `RET` pops `IP` to return to caller. | None. Execution flows forward from the jump target. |
| **High-Level Analogy** | Calling a function: `myFunction();` | `if`, `else`, `goto`, `while`, `for` |
| **Execution Flow** | Deviates temporarily, then returns. | Permanently transfers execution to target. |

## 3. Case Study: Dissecting the `print_hex` Routine in `5.1.asm`

```assembly
; In main:
    mov al, bl 
    shr al, 4          ; Get upper 4 bits (nibble)
    call print_hex     ; [1] FUNCTION CALL

    mov al, bl
    and al, 0Fh        ; Get lower 4 bits (nibble)
    call print_hex     ; [2] FUNCTION CALL
    ...

; Subroutine:
print_hex proc
    add al, 48         ; Convert 0-9 to ASCII '0'-'9' (48 = '0')
    cmp al, 57         ; Compare with ASCII '9' (57 = '9')
    jbe out            ; [3] CONDITIONAL JUMP (If al <= '9', skip letter adjustment)
    add al, 7          ; [4] Adjustment for hex digits 10-15 ('A'-'F')
    
   out:                ; [5] BRANCH TARGET LABEL (Not a function)
    mov dl, al
    mov ah, 02h 
    int 21h            ; Print character to console
    ret                ; [6] RETURN to caller

print_hex endp
```

### Trace & Execution Breakdown:

1. **`call print_hex` (Lines 27 & 31)**:
   - Pushes return address onto stack and transfers control to `print_hex`.
2. **ASCII Conversion Math**:
   - Digits `0` through `9` map to ASCII `30h`–`39h` (48–57 in decimal). Adding `48` converts them directly.
   - Digits `10` through `15` (`0Ah`–`0Fh`) must map to ASCII `'A'`–`'F'` (`41h`–`46h` / 65–70 decimal).
   - Adding `48` produces `58` to `63`. To reach `65` (`'A'`), an additional `+7` is needed ($58 + 7 = 65$).

3. **How `cmp al, 57` Evaluates the Value of `AL`**:
   - `cmp dest, src` performs an internal subtraction: **$\text{AL} - 57$**.
   - It **does NOT modify `AL`** (the subtraction result is discarded).
   - It sets the CPU **FLAGS**:
     - **Carry Flag (CF)**: Set to `1` if $\text{AL} < 57$ (an unsigned borrow occurred).
     - **Zero Flag (ZF)**: Set to `1` if $\text{AL} == 57$ (result is zero).
   - **`jbe out` (Jump if Below or Equal)**: Checks if $(\text{CF} = 1 \text{ or } \text{ZF} = 1)$.
     - If $\text{AL} \le 57$ (digits `'0'`–`'9'`), the CPU jumps directly to `out:`, skipping `add al, 7`.
     - If $\text{AL} > 57$ (hex letters `10`–`15`), the jump condition is false, so it falls through to line 44 and adds `7`.

4. **`out:` (Line 46)**:
   - This is **not a function**. It is simply the meeting point (merge label) of the `if-else` path before displaying the character.

5. **`ret` (Line 50)**:
   - Pops the return address stored during step 1 and returns control back to `main`.

### High-Level Language Equivalent (C / C++):
```c
void print_hex(unsigned char al) {
    al += 48;
    if (al > 57) {       // In assembly: inverted condition via `jbe out`
        al += 7;
    }
    // out:
    putchar(al);
}
```

## 4. Key Takeaways & Best Practices

1. **Use `PROC ... ENDP` for Functions**: Always wrap reusable subroutines in `proc` blocks and terminate them with `ret`.
2. **Use Labels (`label:`) for Branching**: Use local labels with conditional jumps (`je`, `jne`, `jb`, `jbe`, `ja`, `jae`) for `if-else` logic and loops.
3. **Never Forget `ret` in a Procedure**: Without `ret`, the CPU will not return to `main`; it will fall through and execute whatever instructions follow sequentially in memory, leading to crashes or undefined behavior.
4. **Preserve Registers When Needed**: If a procedure alters registers that the caller depends on, use `PUSH` at the start and `POP` in reverse order before `RET`.

## 5. Branch Label Reach & Jump Ranges

A branch label is **not restricted to the immediate next line**. Labels mark arbitrary points in memory, allowing forward jumps (skipping code blocks) or backward jumps (loops).

### 1. Forward Branching (Skipping Code)
Used for conditional execution like `if-else` blocks:
```assembly
    cmp al, 'Q'
    je quit_program       ; Jumps forward over many instructions

    ; Multiple lines of processing...
    mov bx, 10
    add ax, bx

quit_program:
    mov ah, 4Ch
    int 21h
```

### 2. Backward Branching (Loops)
Used to repeat execution:
```assembly
    mov cx, 5
repeat_loop:
    mov ah, 02h
    mov dl, '*'
    int 21h
    dec cx
    jnz repeat_loop       ; Jumps backward to repeat_loop
```

### 3. 8086 Jump Distance Limits
- **Conditional Jumps (`JE`, `JNE`, `JB`, `JBE`, etc.)**: Use an 8-bit signed relative offset, giving a reach of **$-128$ to $+127$ bytes** (roughly 40–60 instructions).
- **Near Unconditional Jump (`JMP label`)**: Uses a 16-bit relative offset, reaching anywhere within the **64 KB segment** ($-32,768$ to $+32,767$ bytes).
- **Far Jump (`JMP FAR PTR label`)**: Reaches across different segments by changing both `CS` and `IP`.

## 6. ASCII Range Checking & Conditional Jumps

### `CMP` and `JBE` Mechanics
In `5.1.asm` line 42–43:
```assembly
cmp al, 57    ; Evaluates (AL - 57), sets flags without changing AL
jbe out       ; Jumps if AL <= 57 (CF = 1 OR ZF = 1)
```
- **`JBE` (Jump if Below or Equal)** is **TRUE** for any unsigned value **$\le 57$** (i.e. both when `AL < 57` and when `AL == 57`).
- In ASCII, `57` (decimal) is `'9'` (`39h`). Thus, `jbe out` matches any ASCII character from `0` up to `'9'`.

---

### ASCII Character Table Reference

| Category | Decimal Range | Hex Range | Character Range | Preceding Character |
| :--- | :--- | :--- | :--- | :--- |
| **Digits** | `48` – `57` | `30h` – `39h` | `'0'` – `'9'` | `'/'` (`2Fh` / 47) |
| **Uppercase** | `65` – `90` | `41h` – `5Ah` | `'A'` – `'Z'` | `'@'` (`40h` / 64) |
| **Lowercase** | `97` – `122` | `61h` – `7Ah` | `'a'` – `'z'` | ``` ` ``` (`60h` / 96) |

---

### How to Check Character Ranges (Capital vs. Small Letters)

To verify whether a character falls strictly within a range (e.g. $[41h, 5Ah]$ for capital letters), you perform a **two-boundary check**:

#### 1. Checking for Capital Letters (`'A'` – `'Z'` / `41h` – `5Ah`)
```assembly
; Check if AL is an uppercase letter:
    cmp al, 'A'          ; Compare with lower boundary (41h / 65)
    jb  not_capital      ; If AL < 'A', it's NOT capital
    cmp al, 'Z'          ; Compare with upper boundary (5Ah / 90)
    ja  not_capital      ; If AL > 'Z', it's NOT capital

    ; --- If we reach here, AL is guaranteed to be 'A'-'Z' ---
    ; [Handle Capital Letter Logic]

not_capital:
```

#### 2. Checking for Small Letters (`'a'` – `'z'` / `61h` – `7Ah`)
```assembly
; Check if AL is a lowercase letter:
    cmp al, 'a'          ; Compare with lower boundary (61h / 97)
    jb  not_small        ; If AL < 'a', it's NOT lowercase
    cmp al, 'z'          ; Compare with upper boundary (7Ah / 122)
    ja  not_small        ; If AL > 'z', it's NOT lowercase

    ; --- If we reach here, AL is guaranteed to be 'a'-'z' ---
    ; [Handle Small Letter Logic]

not_small:
```

#### 3. Comparing with `'a'` vs. `60h` (Character Before `'a'`)
- You **do not need to compare with `60h`** (the backtick ``` ` ```).
- Comparing directly with `'a'` and using `JB` (Jump if Below) cleanly rejects anything $< \text{'a'}$.
- Using character literals (`cmp al, 'a'`) is preferred over raw hex (`cmp al, 61h`) or offset comparisons (`cmp al, 60h`) because it makes the assembly code self-documenting and eliminates off-by-one errors.

| Approach | Assembly Instruction | Jump Condition | Readability |
| :--- | :--- | :--- | :--- |
| **Direct (Recommended)** | `cmp al, 'a'` | `jb not_small` (if $< \text{'a'}$) | ⭐⭐⭐⭐⭐ Self-explanatory |
| **Hex Equivalent** | `cmp al, 61h` | `jb not_small` (if $< 61h$) | ⭐⭐⭐ Requires ASCII lookup |
| **Preceding Char** | `cmp al, 60h` / `cmp al, '`'` | `jbe not_small` (if $\le 60h$) | ⭐ Obscure & prone to bugs |

## 7. Deep Dive: How `JBE` "Knows" the Result of `CMP` (The 8086 FLAGS Register)

In 8086 architecture, **`CMP` and `JBE` are completely decoupled instructions**; `JBE` does **not** read `AL` or `57`. Instead, they communicate indirectly through a special CPU hardware register: the **`FLAGS` Register (Status Register)**.

```
+--------------------+        Modifies        +------------------------+
|   cmp al, 57       |  ===================>  |  8086 FLAGS Register   |
| (Calculates al-57) |                        |  [ ... | ZF | ... | CF ]|
+--------------------+                        +------------------------+
                                                          ||
                                                       Reads Flag
                                                       Bits Only
                                                          \/
                                              +------------------------+
                                              |       jbe out          |
                                              | Tests: (CF=1 OR ZF=1)  |
                                              +------------------------+
```

### 1. What `cmp al, 57` Does Internally
- Performs an internal arithmetic subtraction: **$\text{Temp} = \text{AL} - 57$**.
- **Discards the result** (the contents of `AL` remain untouched).
- **Updates Status Flags** in the `FLAGS` register:
  - **Zero Flag (`ZF`)**: Set to `1` if $\text{AL} == 57$ (result is $0$). Set to `0` if $\text{AL} \ne 57$.
  - **Carry Flag (`CF`)**: Set to `1` if $\text{AL} < 57$ (an unsigned borrow was required). Set to `0` if $\text{AL} \ge 57$.
  - **Sign Flag (`SF`)** and **Overflow Flag (`OF`)**: Updated for signed comparison logic.

### 2. How `jbe out` Evaluates the Condition
- When `jbe` executes immediately after `cmp`, the CPU hardware inspects only the flags:
  $$\text{Jump Condition for JBE} = (\text{CF} == 1) \lor (\text{ZF} == 1)$$
- If either condition is true (meaning $\text{AL} < 57$ or $\text{AL} == 57$), the CPU updates the Instruction Pointer `IP = offset out`.
- If both flags are `0` (meaning $\text{AL} > 57$), `IP` advances sequentially to the next line (`add al, 7`).

> [!IMPORTANT]
> If you put any flag-modifying instruction between `CMP` and `JBE` (such as `ADD`, `SUB`, `AND`, `OR`), those flags will be overwritten and `JBE` will make decisions based on the new operation, not the `CMP`!

## 8. Why You Cannot Replace `CALL print_hex` with `JMP print_hex` (Line 31)

In `5.1.asm`:
```assembly
29:         mov al, bl
30:         and al, 0Fh
31:         call print_hex        ; What if this were `jmp print_hex`?
32:         
33:         mov ah, 4Ch
34:         int 21h
```

### What Happens if You Use `jmp print_hex` at Line 31?

1. **`JMP` Does NOT Push a Return Address**:
   - `CALL print_hex` saves the address of Line 33 (`mov ah, 4Ch`) onto the Stack so the CPU knows where to resume.
   - `JMP print_hex` just jumps directly to `print_hex` without saving anything on the stack.

2. **The Fatal Crash at `RET` (Line 50)**:
   - Inside `print_hex`, line 50 executes `RET`.
   - `RET` **always** pops 2 bytes from the top of the Stack into `IP`.
   - Since `JMP` never pushed line 33 onto the stack:
     - The stack pointer (`SP`) points to whatever old garbage / leftover data was on the stack.
     - `RET` pops that garbage address into `IP`.
     - The CPU begins executing random memory, causing an immediate **crash**, **freeze**, or infinite loop.

3. **Termination Code is Skipped**:
   - Even if `ret` did not crash, lines 33–34 (`mov ah, 4Ch` / `int 21h` — the DOS program termination) would never be reached properly.

```
--- EXECUTION TRACE COMPARISON ---

[Using CALL print_hex]
Main: CALL print_hex ----> (Pushes Line 33 to Stack) ----> Enters print_hex
                                                                |
Main: Line 33 (DOS Exit) <-- (RET pops Line 33 from Stack) <----+

[Using JMP print_hex]
Main: JMP print_hex  ----> (Stack is NOT modified)       ----> Enters print_hex
                                                                |

## 9. Is RET (Line 50) Needed? (RET vs. ENDP Explained)

In [`5.1.asm#L50-L52`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-5_Bitwise_Hex_Display/5.1.asm#L50-L52):

```assembly
50:         ret
51:         
52:     print_hex endp    
53:     
54:    end main
```

A common question is: **"Is `ret` at line 50 needed? Doesn't `print_hex endp` already end the procedure?"**

The short answer: **YES, `ret` is 100% mandatory.**

---

### 1. Positioning: `ret` is BEFORE `endp`, Not After

Notice the order in the source code:
- **Line 50**: `ret` is placed **inside** the procedure body, right before the closing directive.
- **Line 52**: `print_hex endp` marks the syntactic end of the procedure declaration.

If you placed `ret` *after* `print_hex endp`, it would sit outside the procedure entirely in no-man's-land.

---

### 2. The Core Difference: Machine Instruction vs. Assembler Directive

The confusion usually arises from conflating high-level language functions (like C/C++ or Java) with 8086 assembly:

| Concept | `RET` (Line 50) | `ENDP` (Line 52) |
| :--- | :--- | :--- |
| **Classification** | **CPU Machine Instruction** | **Assembler Directive** (Pseudo-op) |
| **Executed By** | 8086 CPU Hardware at **Runtime** | Assembler (MASM/TASM/emu8086) at **Compile Time** |
| **Generated Machine Code** | **1 Byte**: Opcode `C3h` (Near Return) | **0 Bytes** (Generates absolutely nothing) |
| **Action on Hardware** | Pops return address from Stack into `IP`: `POP IP` | Signals assembler that the procedure scope has ended |
| **CPU Awareness** | The CPU executes this to navigate back to `main` | The CPU has **no idea** `endp` exists |

> [!IMPORTANT]
> `ENDP` **does NOT emit a return instruction!** It produces **zero bytes** in the compiled binary `.com` / `.exe`. Its sole purpose is to tell the assembler where the procedure label's scope finishes.

### 3. What Happens If You Remove `RET`?

If you delete `ret` from line 50:

```
Assembly Source Code:                Compiled Machine Code in RAM:
print_hex proc                       Offset 0110: [add al, 48]
    add al, 48                       Offset 0112: [cmp al, 57]
    cmp al, 57                       Offset 0114: [jbe +02]
    jbe out                          Offset 0116: [add al, 7]
    add al, 7                        Offset 0118: [mov dl, al]
   out:                              Offset 011A: [mov ah, 02h]
    mov dl, al                       Offset 011C: [int 21h]
    mov ah, 02h                      ; NO RET! (endp generates nothing!)
    int 21h                          Offset 011E: [Garbage / Next Memory...]
print_hex endp
```

1. When `CALL print_hex` executes from `main`, the CPU pushes the return address (line 32) onto the stack and jumps into `print_hex`.
2. The CPU executes `int 21h` (prints character).
3. **Without `ret`**: The CPU's Instruction Pointer (`IP`) simply steps to the very next byte in memory.
4. Because `endp` does not exist in machine code and there is no subsequent code before `end main`, the CPU starts decoding whatever random, uninitialized memory bytes follow.
5. **Result**: An immediate crash, invalid opcode exception, system freeze, or infinite loop in DOS/emu8086. It will **never** return to line 32 in `main`.

---

### 4. Stack Lifecycle with `CALL` and `RET`

```
  Step 1: CALL print_hex (Main L31)
  ---------------------------------
  Stack Top (SP) ---> [ Return Offset: Line 32 ]   (Saved on stack)
  IP = Offset of print_hex

  Step 2: Procedure Body Executes (L41-L49)
  -----------------------------------------
  Registers modified (AL, DL, AH).
  Stack Top (SP) still holds [ Return Offset: Line 32 ].

  Step 3: RET Executes (L50)
  --------------------------
  CPU pops stack: IP <= [ Return Offset: Line 32 ]
  SP restored to original state.
  Execution resumes cleanly at Line 33 (Program Termination).

  Step 4: ENDP (L52)
  ------------------
  Passive marker for assembler. No CPU action.
```

### 5. Why Doesn't the Assembler Auto-Insert `RET` at `ENDP`?

In C/C++, a closing curly brace `}` at the end of a `void` function automatically generates a return instruction. Why doesn't MASM or emu8086 do this for `endp`?

1. **Assembly Gives Full Control**: A procedure may have multiple conditional return points:
   ```assembly
   check_zero proc
       cmp ax, 0
       jne not_zero
       ret              ; Early return 1
   not_zero:
       mov bx, 1
       ret              ; Return 2
   check_zero endp
   ```
2. **Tail-Calls and Jumps**: A procedure might intentionally end with a `JMP` to another procedure instead of a `RET` (tail-call optimization).
3. **Fall-Through Subroutines**: In optimized low-level programming, developers sometimes deliberately design routines to fall through into adjacent code.

Therefore, assembly assemblers strictly obey your code: if you want the CPU to return, you **must explicitly write `ret`**.
