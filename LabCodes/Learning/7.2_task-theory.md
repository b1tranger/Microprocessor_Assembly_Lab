# Understanding Loop Invariants & Conditional Skip Placement in 8086 Assembly

When writing loops in 8086 assembly language that filter or skip certain items (analogous to an `if (dl == 's') continue;` in high-level languages), the exact placement of label targets like `skip:` is critical. 

Placing the `skip:` label **after** the counter increment instruction (`inc dl`) causes what appears to be an premature halt or silent failure of the loop. This document explains the hardware execution flow, register state mutations, and provides a comparative line-by-line trace.

## 1. The Problem Statement & Code Comparison

Consider the task of printing the lowercase English alphabet from `'a'` to `'z'` while skipping the letter `'s'`:

### Code Structure:
```assembly
    mov cx, 26
    mov dl, 'a'

level:
    cmp dl, 's'
    je skip
    mov ah, 2h 
    int 21h

; Option A (Line 22): skip placed BEFORE inc dl
skip:
    inc dl
; Option B (Line 24): skip placed AFTER inc dl
;skip:
    loop level
```

- **With Option A (Before `inc dl`)**: Prints `abcdefghijklmnopqrtuvwxyz` (25 letters, skipping `'s'`).
- **With Option B (After `inc dl`)**: Prints `abcdefghijklmnopqr` and **abruptly stops printing**! Letters from `'t'` to `'z'` never appear on screen.

---

## 2. Hardware Execution Mechanics (`LOOP` & `JE`)

To understand why the loop appears to stop, look at the two CPU instructions controlling this sequence:

1. **`JE skip` (Jump if Equal)**:
   - Evaluates the Zero Flag ($ZF$).
   - If `DL == 's'`, the CPU sets $ZF = 1$, and `JE` changes the Instruction Pointer ($IP$) directly to the memory address of `skip:`.
   - Any instructions between `JE` and `skip:` are **bypassed completely**.

2. **`LOOP level`**:
   - The 8086 hardware executes two steps atomically:
     $$\text{CX} \leftarrow \text{CX} - 1$$
     $$\text{If } \text{CX} \neq 0 \implies \text{Jump to } level$$
   - `LOOP` does **not** check what character is in `DL`. It only checks if `CX` has reached zero.

---

## 3. Case 1: `skip:` Placed BEFORE `inc dl` (Correct)

```assembly
    cmp dl, 's'
    je skip             ; If DL == 's', jump directly to 'skip'
    mov ah, 2h 
    int 21h             ; <-- BYPASSED when DL == 's'
skip:
    inc dl              ; <-- STILL EXECUTES! 's' becomes 't'
    loop level          ; CX decrements, loop continues with DL = 't'
```

- When `DL = 's'`, `int 21h` is skipped (so `'s'` is not displayed).
- Crucially, `inc dl` **still executes**, transforming `DL` from `'s'` (73h) to `'t'` (74h).
- Next iteration starts with `DL = 't'`, `cmp dl, 's'` is false, and printing resumes normally for `'t'` through `'z'`.

## 4. Case 2: `skip:` Placed AFTER `inc dl` (The Bug)

```assembly
    cmp dl, 's'
    je skip             ; If DL == 's', jump directly to 'skip'
    mov ah, 2h 
    int 21h             ; <-- BYPASSED
    inc dl              ; <-- ALSO BYPASSED! DL is NOT incremented!
skip:
    loop level          ; CX decrements, DL is STILL 's'!
```

When `skip:` is placed **after** `inc dl`:
1. When `DL` reaches `'s'`, `je skip` jumps **over both** the print instruction (`int 21h`) AND the increment (`inc dl`).
2. `DL` **never becomes `'t'`**. It remains `'s'`.
3. `loop level` decrements `CX` and jumps back to `level`.
4. In the very next iteration, `DL` is still `'s'`.
5. `cmp dl, 's'` is again true! `je skip` jumps again, bypassing print and increment again!
6. For all remaining 8 iterations (`CX = 8, 7, 6, 5, 4, 3, 2, 1`), the loop runs **silently**:
   - `DL` is frozen at `'s'`.
   - Nothing is printed.
   - `inc dl` never runs.
   - `CX` decrements silently until it hits `0`.
7. Once `CX == 0`, `LOOP` finishes and control falls through to `exit:` (`int 21h, ah=4ch`).

The user sees the output stop at `'r'` because all remaining iterations loop as no-ops without ever updating `DL`.

## 6. High-Level Language (C/C++) Equivalence

This bug is identical to placing a `continue` statement in a `while` loop before incrementing the loop variable:

### Buggy C Logic (Corresponds to `skip` after `inc dl`):
```c
char dl = 'a';
int cx = 26;

while (cx > 0) {
    if (dl == 's') {
        goto skip; // Bypasses both putchar AND dl++!
    }
    putchar(dl);
    dl++;          // <-- SKIPPED!

skip:
    cx--;
}
// dl stays 's' forever; cx runs down to 0 without printing t-z.
```

### Correct C Logic (Corresponds to `skip` before `inc dl`):
```c
char dl = 'a';
int cx = 26;

while (cx > 0) {
    if (dl != 's') {
        putchar(dl);
    }
    dl++; // Always executed on every pass!
    cx--;
}
```

## 7. Summary & Key Rules for Loop Design

1. **Distinguish Loop Body from Step/Update Invariant**:
   - An action you want to **filter** (e.g., printing) belongs inside the conditional branch.
   - An action that **advances the loop state** (e.g., `inc dl`, `add si, 2`) must remain common to **all** iterations unless you explicitly want to freeze the state.
2. **Where to place `skip:`**:
   - Place `skip:` right before the state advancement instructions (`inc dl`), so filtered elements still step forward to the next value.
