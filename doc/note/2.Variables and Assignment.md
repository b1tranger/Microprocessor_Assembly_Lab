## 1. High-Level Concept

In high-level languages like C:
```c
int count = 10;
count = count + 5;
```
The compiler abstracts away the loading of data from RAM into CPU registers and storing the updated result back into memory.

---

## 2. 8086 Assembly Implementation

In 8086 assembly, memory variables must be declared within the data segment (`.data`), and modifications require explicitly shuttling data through CPU registers:

```assembly
.data
    count dw 10          ; Allocate 16-bit word initialized to 10

.code
main proc
    mov ax, @data        ; Initialize DS segment register
    mov ds, ax

    mov ax, count        ; Load value from memory [DS:offset count] into register AX
    add ax, 5            ; ALU computes AX + 5, updates FLAGS
    mov count, ax        ; Store result back into RAM at [DS:offset count]
```

---

## 3. Register-Level Mechanics & Hardware Rules

- **Data Allocation Directives**:
  - `DB` (Define Byte): Allocates 8 bits of memory ($1\text{ byte}$).
  - `DW` (Define Word): Allocates 16 bits of memory ($2\text{ bytes}$).
  - `DD` (Define Doubleword): Allocates 32 bits of memory ($4\text{ bytes}$).
- **Scratchpad Role**: General-purpose registers (`AX`, `BX`, `CX`, `DX`) serve as high-speed scratchpads. ALU operations (`ADD`, `SUB`, `MUL`, `DIV`, `AND`, `OR`) operate primarily between registers and memory, or register and immediate values.

---

## 4. Memory-to-Memory Prohibition

> [!IMPORTANT]
> The 8086 architecture **does not support direct memory-to-memory operations**.
> 
> ```assembly
> mov [var2], [var1]     ; ILLEGAL: 8086 cannot move memory to memory
> add [var2], [var1]     ; ILLEGAL: Cannot add memory directly to memory
> ```
> 
> You must route values through an intermediate CPU register:
> ```assembly
> mov ax, [var1]         ; Valid: Memory to Register
> mov [var2], ax         ; Valid: Register to Memory
> ```
