## 1. ALU Instructions Never Require `INT 21h`

> [!CAUTION]
> **ALU operations are internal CPU machine instructions. They are NOT DOS system calls.**

Instructions such as `ADD`, `SUB`, `MUL`, `DIV`, `AND`, `OR`, `XOR`, `SHL`, `SHR`, `ROL`, `ROR`, and `CMP` execute entirely within the CPU silicon. They do **not** interact with the operating system.

### The Lingering `AH` Trap:
If you execute `int 21h` after an ALU instruction (e.g. `rol al, 1; int 21h`):
- The CPU triggers software interrupt `21h`.
- DOS looks at whatever value happens to remain in **`AH`** from earlier instructions.
- If `AH` previously held `09h` (string display), DOS executes Service `09h` a second time, duplicating your message on screen.
- If `AH` held `02h`, it outputs whatever character byte remains in `DL`.

**Rule**: Only invoke `INT 21h` when you explicitly set `AH` to a recognized DOS service number (`01h`, `02h`, `09h`, `4Ch`).

## 2. Garbage Clearing & Register Hygiene

Registers in 8086 retain residual data from previous calculations unless explicitly overwritten or reset.

### A. Clearing a Byte or Word
```assembly
mov al, 0        ; Sets AL to 0 (2 bytes: B0 00)
xor al, al       ; Idiomatic: Clears AL to 0 in 2 bytes, sets ZF=1
xor ax, ax       ; Clears full 16-bit AX register
```

### B. The Division Trap: Zeroing `AH` Before 8-Bit Division
In 8086 assembly, an 8-bit division (`DIV BL`) divides the entire **16-bit register `AX`** by `BL`:
$$\text{Quotient} = \text{AX} / \text{BL} \quad (\text{stored in AL}), \quad \text{Remainder} = \text{AX} \pmod{\text{BL}} \quad (\text{stored in AH})$$

If `AH` contains leftover data, the dividend is huge, triggering a catastrophic **Divide Error Fault (`#DE`)**:
```assembly
; WRONG:
mov al, 14
div bl           ; CRASH: AX is actually [garbage:14], not 14!

; CORRECT:
mov ah, 0        ; Or: xor ah, ah
mov al, 14
div bl           ; Safe: AX is strictly 000Eh (14)
```

## 3. Program Termination Mechanics (`MOV AH, 4Ch`)

Every 8086 DOS executable must explicitly surrender control back to the operating system:

```assembly
mov ah, 4Ch      ; Service 4Ch: Terminate process with return code
mov al, 0        ; Exit code 0 (success) - or simply: mov ax, 4C00h
int 21h          ; Hand control back to DOS
```

### What happens if omitted?
If you forget `MOV AH, 4Ch; INT 21h`, the CPU does not stop at `ENDP` or `END`. It continues fetching memory bytes past your code segment, attempting to decode data, strings, or random RAM as instructions, resulting in hangs, crashes, or infinite loops.

## 4. Tri-Representation of ASCII (`'0'`, `48`, `30h`)

In 8086 assembly, the assembler treats character literals, decimal integers, and hexadecimal quantities identically at the machine level:

| Representation | Syntax | Stored Binary | Decimal Value |
| :--- | :--- | :--- | :--- |
| Character Literal | `'0'` | `0011 0000b` | $48$ |
| Decimal Integer | `48` | `0011 0000b` | $48$ |
| Hexadecimal Literal | `30h` | `0011 0000b` | $48$ |

These instructions generate the exact same machine code:
```assembly
add al, '0'      ; Recommended: Maximizes code readability
add al, 48       ; Identical machine code
add al, 30h      ; Identical machine code
```

### Case Conversion Quick Fact:
- Uppercase `'A'` = `41h` (`65d` = `0100 0001b`)
- Lowercase `'a'` = `61h` (`97d` = `0110 0001b`)
- They differ **only at Bit 5** ($2^5 = 32 = 20\text{h}$).
- Toggling case: `XOR AL, 32` (or `XOR AL, 20h`).

## 5. Hexadecimal Output Math: Why Both `+48` and `+7` Are Needed

A 4-bit nibble holds numeric values from $0$ to $15$ ($0\text{h} \dots 0\text{Fh}$).
- Values $0 \dots 9$ map to ASCII `'0'` $\dots$ `'9'` ($48 \dots 57$). Adding `48` converts them directly.
- Values $10 \dots 15$ map to ASCII `'A'` $\dots$ `'F'` ($65 \dots 70$).
- Notice the gap: $58$ to $64$ in the ASCII table contains punctuation (`:`, `;`, `<`, `=`, `>`, `?`, `@`).
- To bridge the gap from $58$ (`':'`) to $65$ (`'A'`), you must add an extra **$7$**:

```assembly
print_hex proc
    add al, 48       ; Step 1: Base offset for '0'-'9'
    cmp al, 57       ; Compare with ASCII '9'
    jbe is_digit     ; If <= '9', conversion is complete
    add al, 7        ; Step 2: Bridge 7-character gap for 'A'-'F'
is_digit:
    mov dl, al
    mov ah, 02h
    int 21h
    ret
print_hex endp
```

> [!IMPORTANT]
> If you omit `add al, 48`, `AL` holds raw values $0\dots 15$. `cmp al, 57` is always true, and sending values $0\dots 15$ to `INT 21h, AH=02h` emits **invisible ASCII control characters** (NUL, SOH, STX), making your output look blank!

## 6. DOS `INT 21h` Core Services Summary

| Service (`AH`) | Purpose | Input Parameter | Output / Return Value | Notes |
| :--- | :--- | :--- | :--- | :--- |
| **`01h`** | Read Character with Echo | None | Character returned in **`AL`** | Waits for keystroke; echoes to screen |
| **`02h`** | Write Character | Character placed in **`DL`** | `AL = DL` | Outputs single character to active screen |
| **`09h`** | Write String | String offset placed in **`DX`** | None | String in DS must be terminated with **`$`** |
| **`4Ch`** | Terminate Process | Return code in **`AL`** | Returns to DOS | Mandatory exit instruction |

## 7. The 8086 Shift/Rotate Count Hardware Constraint

In the original 8086/8088 CPU, immediate shift counts can **only be 1**:

```assembly
; VALID on 8086:
shr al, 1
rol al, 1

; INVALID on original 8086 hardware (requires 80186+):
shr al, 4        ; Emulators may accept this, but strict 8086 rejects it!

; STRICT 8086 STANDARD for count > 1:
mov cl, 4        ; Load count into CL register
shr al, cl       ; Shift using CL
```

## 8. Direct Memory-to-Memory Moves Are Illegal

The 8086 instruction set architecture strictly forbids reading from memory and writing to memory in a single instruction:

```assembly
mov [dest_var], [src_var]   ; ILLEGAL: 8086 cannot move memory to memory

; Correct 2-step transfer:
mov ax, [src_var]           ; Step 1: Memory -> Register
mov [dest_var], ax           ; Step 2: Register -> Memory
```

## 9. The DOS String Sentinel Rule (`$`)

When using DOS Service `09h` (`INT 21h / AH=09h`), the operating system prints characters starting at address `DS:DX` until it encounters a literal dollar sign (`$` = ASCII `24h`).

```assembly
.data
    ; CORRECT:
    greeting db 'Hello, World!$'

    ; DANGEROUS (Missing $):
    bad_msg  db 'Error ahead'     ; Prints 'Error ahead' plus whatever garbage
                                  ; follows in RAM until a random 24h byte is hit!
```

## 10. Embedded CRLF (`13, 10`) & Multi-Line String Declarations Under a Single Variable

In console applications, formatting output with clean newlines is a fundamental requirement. Beginners often write repetitive interrupt blocks to emit newlines:

```assembly
; THE SLOW, REPETITIVE WAY (Multiple INT 21H calls):
mov ah, 2
mov dl, 13           ; Carriage Return
int 21h
mov ah, 2
mov dl, 10           ; Line Feed
int 21h
```

### Understanding CRLF:
* **`13` (`0Dh`) = Carriage Return (`\r`)**: Resets the cursor horizontally back to the beginning of the line (Column 0).
* **`10` (`0Ah`) = Line Feed (`\n`)**: Advances the cursor vertically down to the next row.
* **Why both are required**: In DOS / Windows console emulation, emitting `10` alone produces a "staircase effect" (moving down without returning to the left), while emitting `13` alone moves to the left and causes the next output to overwrite the current line.

---

### Declaring Multiple Strings Under a Single Variable (Multi-Line String)

As demonstrated in [`string_printing_lea.asm#L20-L23`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-8_Labtest-1/prep/string_printing_lea.asm#L20-L23), you can declare multi-line messages under **one single variable name** in the `.data` segment:

```assembly
.data
    ; Multi-line string with embedded Carriage Return (13) and Line Feed (10):
    msg_lea_demo    db 13, 10, '[Approach 1: LEA + Embedded CRLF]'
                    db 13, 10, ' Line 1: Using LEA DX, label'
                    db 13, 10, ' Line 2: Multi-line emitted in a SINGLE INT 21H call!'
                    db 13, 10, ' Line 3: No repeated INT 21H (AH=02h) calls needed.$'
```

### How It Works at the Memory & Assembler Level:
1. **Contiguous Memory Allocation**: The symbol `msg_lea_demo` marks the memory address of the first byte (`13`).
2. Subsequent lines declared with `db` without a new label are placed **immediately and contiguously in adjacent memory bytes**.
3. **Single System Call**: When you pass `DX = offset msg_lea_demo` (or `lea dx, msg_lea_demo`) to `INT 21h / AH=09h`:
   ```assembly
   lea dx, msg_lea_demo
   mov ah, 09h
   int 21h
   ```
   DOS reads through all lines, executes the embedded `13, 10` sequences, and only stops when it finally encounters the trailing `$` at the end of Line 3!
4. **Efficiency Gain**: Replaces dozens of repetitive instructions with a **single DOS interrupt**, keeping your code clean and significantly reducing binary size.

## 11. Stack Alignment & Register Preservation

The 8086 stack operations (`PUSH` and `POP`) strictly operate on **16-bit words**:
- You cannot `push al` or `pop bl` (8-bit registers cannot be pushed).
- Every `PUSH` decrements `SP` by 2 (`SP = SP - 2`).
- Every `POP` increments `SP` by 2 (`SP = SP + 2`).
- Subroutines that modify registers must preserve them using `PUSH` at the entry and `POP` in **reverse order** before `RET`:

```assembly
my_subroutine proc
    push ax          ; Save caller's AX
    push bx          ; Save caller's BX

    ; ... logic modifying AX and BX ...

    pop bx           ; Restore in LIFO order
    pop ax
    ret
my_subroutine endp
```

## 12. Equivalent Assembly Idioms & Alternative Code Patterns (Cheat Sheet)

In 8086 assembly, multiple syntactical idioms achieve identical results. Understanding both forms allows you to read and write flexible, optimized code.

### Master Equivalence Lookup Table

| Common Idiom | Alternative / Idiomatic Syntax | What They Do | Difference / Trade-offs |
| :--- | :--- | :--- | :--- |
| **`mov dx, offset msg`** | **`lea dx, msg`** | Loads address of string for `INT 21h / AH=09h` | `OFFSET` evaluates at assemble-time (static immediate). `LEA` computes at runtime and supports compound addressing like `[bx+si+5]`. |
| **`mov al, 0`** | **`xor al, al`** (or `sub al, al`) | Clears register to zero | `XOR` is shorter (2 bytes), faster, and sets `ZF=1`. `MOV` is 2 bytes (or 3 bytes for 16-bit) and leaves flags untouched. |
| **`mov ah, 4ch`<br>`mov al, 00h`<br>`int 21h`** | **`mov ax, 4c00h`<br>`int 21h`** | Terminates program with exit code 0 | Combining `AH=4Ch` and `AL=00h` into a single 16-bit load (`MOV AX, 4C00h`) saves 1 instruction and 2 bytes of code. |
| **`add al, 1`** | **`inc al`** | Increments register by 1 | `INC` is smaller/faster, but **does NOT affect the Carry Flag (`CF`)**! `ADD` updates all arithmetic flags including `CF`. |
| **`sub al, 1`** | **`dec al`** | Decrements register by 1 | `DEC` does **NOT** modify `CF`. `SUB` updates `CF`. |
| **`cmp al, 0`** | **`test al, al`** (or `or al, al`) | Checks if register is zero | `TEST` performs bitwise AND without storing, updating `ZF` and `SF`, clearing `CF` and `OF`. Leaves operands intact. |
| **`shl al, 1`** | **`add al, al`** | Multiplies unsigned number by 2 | Both shift left by 1 and set `CF` from MSB. `ADD AL, AL` is often 1 cycle faster on older 8086 hardware. |
| **`add al, '0'`** | **`add al, 48`** or **`add al, 30h`** | Converts binary digit (0–9) to ASCII | Identical binary opcode. `'0'` improves readability. |
| **`sub al, '0'`** | **`sub al, 48`** or **`sub al, 30h`** | Converts ASCII digit ('0'–'9') to integer | Identical binary opcode. |
| **`xor al, 32`** | **`xor al, 20h`** or **`xor al, ' '`** | Inverts uppercase/lowercase ASCII letter | Toggles Bit 5 ($2^5 = 32 = 20\text{h}$). Identical machine code. |

### Deep Dive: `LEA` vs. `MOV DX, OFFSET`

Both instructions stage the memory address of a string into `DX` for DOS Service `09h`:

```assembly
; Approach 1: Using OFFSET (Static Assembler Immediate)
mov dx, offset msg1
mov ah, 09h
int 21h

; Approach 2: Using LEA (Runtime Effective Address)
lea dx, msg1
mov ah, 09h
int 21h
```

#### When to Use Which:
1. **Simple Direct Labels (`.data`)**:
   - Both produce the identical effective runtime pointer in `DX`.
   - `MOV DX, OFFSET msg` is an immediate instruction where the offset is hardcoded directly into the machine code by the assembler.
   - `LEA DX, msg` uses the CPU ALU to compute the address.
2. **Dynamic / Indexed Memory Offsets**:
   - `OFFSET` **cannot** be used with register pointers: `mov dx, offset [bx+si]` is **illegal**.
   - `LEA` supports dynamic runtime pointer calculations:
     ```assembly
     lea dx, [bx + si + 4]    ; Perfectly legal: computes runtime pointer
     ```
