## 1. Fundamental Comparison Mechanics (`CMP` & Status Flags)

In the 8086 CPU, comparison does not modify memory or destination registers. It is implemented purely through subtraction:
$$\text{CMP destination, source} \implies \text{ALU calculates } (\text{destination} - \text{source})$$

The ALU evaluates the mathematical difference, updates the status flags in the `FLAGS` register, and discards the numerical result.

```
+--------------------+
|  CMP Register, Src |
+--------------------+
          |
          v
+--------------------+
| ALU: Dest - Src    |
+--------------------+
          |
          v
+--------------------+
| FLAGS Register:    |
| ZF, SF, OF, CF, AF |
+--------------------+
```

## 2. Signed vs. Unsigned Number Branching Guidelines

Choosing the wrong conditional jump family causes critical bugs when values cross the signed boundary (Bit 7 / MSB set):

| Data Type | Value Range (Byte) | Meaning of Bit 7 | Jump Family | Flag Evaluation |
| :--- | :--- | :--- | :--- | :--- |
| **Unsigned** | $0 \dots 255$ (`00h`–`FFh`) | Magnitude ($2^7 = 128$) | `JA`, `JB`, `JAE`, `JBE` | Carry Flag (`CF`), Zero Flag (`ZF`) |
| **Signed** | $-128 \dots +127$ | Sign Bit (`1` = negative) | `JG`, `JL`, `JGE`, `JLE` | Sign (`SF`), Overflow (`OF`), Zero (`ZF`) |
| **Character Codes (ASCII)** | $0 \dots 127$ ($0 \dots 255$ ext) | ASCII Code Point | **Use `JA`, `JB`** | Unsigned magnitude strictly |

> [!TIP]
> Single ASCII digits `'0'`–`'9'` (`30h`–`39h`) have Bit 7 = `0`. While signed jumps (`JG`/`JL`) happen to work for digits `0` through `9`, always write **`JA`/`JB`** for characters, memory offsets, and unsigned quantities.

## 3. Two-Variable Comparison Archetype

When comparing two variables $A$ and $B$, exactly one of three states must hold:
1. $A > B$
2. $A < B$
3. $A == B$

### Standard 8086 Idiom with Fallthrough

```assembly
    mov al, a
    mov bl, b
    cmp al, bl
    ja  a_is_greater        ; Branch if A > B
    jb  b_is_greater        ; Branch if B > A

    ; If neither JA nor JB was taken, A == B must be TRUE
both_equal:
    ; Handle A == B case
    jmp exit_compare

a_is_greater:
    ; Handle A > B case
    jmp exit_compare

b_is_greater:
    ; Handle B > A case

exit_compare:
```

## 4. Three-Variable Decision Tree (Nested Branching)

### The Tournament Model

To find the maximum among three numbers ($A, B, C$) using direct branching:
1. Compare $A$ and $B$.
2. The winner of Step 1 is compared against $C$.
3. Exactly **two comparison instructions** are executed for any input permutation.

```
             [ CMP A, B ]
            /            \
       (A >= B)         (B > A)
         /                  \
   [ CMP A, C ]        [ CMP B, C ]
   /          \        /          \
(A >= C)    (C > A) (B >= C)    (C > B)
   |           |       |           |
Max = A     Max = C Max = B     Max = C
```

### The "Partial Equality" Trap

A frequent mistake in student assembly codes is treating the equality of a single pair as proof that all variables are equal:

```assembly
; BUGGY LOGIC:
mov al, a
cmp al, b
je all_equal          ; FATAL FLAW: A == B does NOT mean A == B == C!
```

If $A = 4, B = 4, C = 9$:
- $A == B$ evaluates to TRUE.
- Program announces "All are equal", completely ignoring that $C = 9$ is the actual maximum!

**Correct Compound Equality Check**:
```assembly
    mov al, a
    cmp al, b
    jne not_all_equal       ; If A != B, cannot all be equal
    cmp al, c
    jne not_all_equal       ; If A != C, cannot all be equal

    ; Both passed: A == B == C
    ; Handle all equal case...
```

## 5. The "Running Extremum" Pattern (Candidate Filter)

### Algorithmic Principle

Instead of exploding into nested branch trees that duplicate code across multiple labels, the **Running Extremum** pattern maintains a single candidate in a register:
1. Initialize `Candidate = A`.
2. Compare `Candidate` with $B$. If $B > \text{Candidate}$, set $\text{Candidate} = B$.
3. Compare `Candidate` with $C$. If $C > \text{Candidate}$, set $\text{Candidate} = C$.
4. `Candidate` now holds $\max(A, B, C)$.

### 8086 Assembly Register Implementation

```assembly
    ; Finding Maximum of A, B, C:
    mov al, a               ; AL holds current running maximum (initialized to A)

    cmp b, al               ; Compare B with current maximum
    jbe check_c             ; If B <= AL, keep current maximum
    mov al, b               ; Otherwise, update maximum to B

check_c:
    cmp c, al               ; Compare C with current maximum
    jbe finished            ; If C <= AL, keep current maximum
    mov al, c               ; Otherwise, update maximum to C

finished:
    ; AL now contains the true maximum!
```

### Scalability to $N$ Numbers

The Running Extremum pattern naturally maps into a `LOOP` construct for arrays of any size:

```assembly
    ; Finding Maximum in an array of N elements:
    lea si, array           ; SI points to start of array
    mov cx, count           ; CX = number of elements
    mov al, [si]            ; AL = candidate (first element)
    inc si
    dec cx                  ; One element processed
    jz  done_search

search_loop:
    cmp [si], al            ; Compare current element with candidate
    jbe next_item
    mov al, [si]            ; Update candidate if larger

next_item:
    inc si
    loop search_loop

done_search:
    ; AL contains the maximum value in the array
```

## 6. Hardware Performance & Instruction Count Comparison

| Metric | Nested Decision Tree | Running Maximum Pattern |
| :--- | :--- | :--- |
| **Comparisons Executed** | Exactly 2 | Exactly 2 (for 3 elements) |
| **Code Footprint** | Large (many labels and `JMP` exits) | Minimal (straightforward linear flow) |
| **Risk of Equality Bugs** | **High** (easy to mishandle ties) | **Zero** (ties preserve existing candidate) |
| **Scalability ($N > 3$)** | Impossible ($N!$ branch explosion) | Seamless (scales as $O(N)$ with `LOOP`) |

## 7. High-Yield Summary Rules

1. **`CMP` is a non-destructive subtraction**: Operands remain unchanged; only `FLAGS` are updated.
2. **Use `JA`/`JB` for character comparisons**: Single-byte inputs from keyboard are unsigned ASCII codes.
3. **Never branch on $A == B$ without testing $C$**: Two equal elements in a 3-element set do not imply uniform equality.
4. **Prefer Running Maximum for Extrema**: When only the maximum or minimum value is required, avoid complex nested trees and use linear candidate replacement.
5. **Always terminate DOS programs with `INT 21h, AH=4Ch`**: Never leave `mov ah, 4ch` hanging without the interrupt trigger.
