# 7. Switch / Case Statements & Jump Tables

This document explains constant-time $O(1)$ multi-branching in 8086 assembly using indirect jump tables via code pointers.

## 1. High-Level Concept

```c
switch (val) {
    case 0: func0(); break;
    case 1: func1(); break;
    case 2: func2(); break;
    default: default_func(); break;
}
```

---

## 2. Linear Search vs. Jump Table Trade-offs

- **Small/Sparse Switch Cases**: Implemented using an `ELSE-IF` ladder of sequential comparisons (`CMP val, 0; JE ...`, `CMP val, 1; JE ...`). Time complexity is $O(N)$.
- **Dense Sequential Cases**: Implemented using an array of function/label memory offsets (a **Jump Table**). The CPU calculates the address dynamically, achieving **$O(1)$ constant-time dispatching**.

---

## 3. 8086 Assembly Jump Table Implementation

```assembly
.data
    val         dw 1
    ; Array of 16-bit code offsets (2 bytes per entry):
    jump_table  dw offset case_0, offset case_1, offset case_2

.code
main proc
    mov ax, @data
    mov ds, ax

    mov bx, val          ; Load selector value
    cmp bx, 2
    ja  default_case     ; Boundary check: if val > 2, branch to default

    shl bx, 1            ; Scale index: multiply by 2 (each word address is 2 bytes)
    jmp jump_table[bx]   ; Indirect Near Jump to address at [jump_table + BX]

case_0:
    call func0
    jmp end_switch       ; Equivalent to 'break'

case_1:
    call func1
    jmp end_switch       ; Equivalent to 'break'

case_2:
    call func2
    jmp end_switch       ; Equivalent to 'break'

default_case:
    call default_func

end_switch:
    ; Resumes normal flow
```

---

## 4. Hardware Execution Mechanics

1. **Boundary Guard**: An initial `CMP bx, 2; JA default_case` is mandatory to avoid jumping into random memory outside the table boundaries.
2. **Word Index Scaling**: Because each memory offset in the table is a 16-bit word ($2\text{ bytes}$), `SHL BX, 1` multiplies the case integer index by 2.
3. **Indirect Jump (`JMP [table + BX]`)**: The CPU reads the target offset stored at that memory location and loads it directly into the Instruction Pointer (`IP`).
