## 3. Code Inspected & Created

The following five standalone, verified assembly programs were authored in [`LabCodes/Labtest/prep/`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep):

### 3.1 `arithmetic_operations.asm`
[`arithmetic_operations.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep/arithmetic_operations.asm)
- Implements interactive user input for two single digits, converts from ASCII (`SUB AL, '0'`), and performs `ADD`, `SUB` (with negative result detection), `MUL` (product in `AX`), and `DIV` (quotient in `AL`, remainder in `AH`).
- Includes a dedicated `print_two_digits` procedure using radix-10 division (`DIV 10`) to display two-digit results cleanly.
- Enforces register clearing hygiene (`XOR AH, AH`) before 8-bit hardware division.

### 3.2 `string_printing_lea.asm`
[`string_printing_lea.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep/string_printing_lea.asm)
- Contrasts runtime effective addressing (`LEA DX, label`) against compile-time immediate constant resolution (`MOV DX, OFFSET label`).
- Demonstrates embedded CRLF (`DB 13, 10, '...'`) for multi-line display in a single DOS interrupt `INT 21H / AH=09H`.
- Demonstrates byte-by-byte null-terminated string printing via pointer `[SI]` and `INT 21H / AH=02H`, eliminating reliance on the DOS `$` sentinel character.

### 3.3 `bitwise_and_or_shift_rotate.asm`
[`bitwise_and_or_shift_rotate.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep/bitwise_and_or_shift_rotate.asm)
- Exercises bitwise `AND`, `OR`, `XOR`, `SHL`, `SHR`, `ROL`, and `ROR`.
- Adheres to the pure 8086 architectural requirement of utilizing `CL` for multi-bit shift/rotate counts ($N > 1$).
- Implements a modular `print_binary_8bit` subroutine shifting MSBs into the Carry Flag to format 8-bit binary representation.

### 3.4 `print_hexadecimal_values.asm`
[`print_hexadecimal_values.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep/print_hexadecimal_values.asm)
- Provides modular subroutines `print_hex_nibble`, `print_hex_byte`, and `print_hex_word`.
- Extracts high and low nibbles using `SHR AL, 4` and `AND AL, 0Fh`.
- Converts nibbles `0-9` via `+ '0'` and `10-15` via `+ 7` (ASCII 55 total offset).
- Implements full register preservation via `PUSH`/`POP` for robust procedural hygiene.

### 3.5 `case_conversion_xor.asm`
[`case_conversion_xor.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/Labtest/prep/case_conversion_xor.asm)
- Implements universal bidirectional case toggling with `XOR AL, 20h` (flipping bit 5).
- Performs boundary validation against `'A'..'Z'` and `'a'..'z'` to prevent corrupting non-alphabetic characters.
- Includes a batch string in-place toggling loop using `LEA SI, sample_str`.

## 4. Analysis & Key Architectural Insights

### 4.1 LEA vs OFFSET Dynamics
- `MOV DX, OFFSET label` encodes the immediate 16-bit displacement directly into the instruction at assemble time.
- `LEA reg16, mem` calculates the effective address in the CPU Execution Unit (EU) during runtime, allowing base and index register combinations (`[BX+SI+disp]`).

### 4.2 Universal XOR Bit 5 Case Toggling
- In ASCII, uppercase letters span `41h` ('A') to `5Ah` ('Z') (`010x xxxx`), while lowercase letters span `61h` ('a') to `7Ah` ('z') (`011x xxxx`).
- The only bit distinguishing lowercase from uppercase is bit 5 (`20h` = 32 decimal).
- Toggling with `XOR AL, 20h` inverts bit 5 in a single clock cycle without requiring separate `ADD` and `SUB` branches.

### 4.3 Pure 8086 CL Register Shift Rule
- In the original 8086 CPU, immediate shift counts greater than 1 (`SHL AL, 2`) are invalid opcodes; the count must be loaded into register `CL`.
- Immediate multi-bit shifts were only introduced starting with the 80186 processor.

### 4.4 Division Hygiene & Decimal Decomposition
- `DIV BL` divides the 16-bit dividend in `AX` by `BL`.
- Leaving uninitialized data in `AH` causes divide overflows (`Fault #DE`). Executing `XOR AH, AH` guarantees a clean 8-bit divide.
- Dividing any value $< 100$ by 10 decomposes it into `AL` (tens) and `AH` (units) for ASCII conversion (`+ '0'`).
