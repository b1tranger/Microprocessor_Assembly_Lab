## 3. Analysis & Key Insights

1. **Compile-Time vs. Runtime Disconnect**:
   - In high-level languages (C, Java, Python), `/` is a runtime division operator (`c = a / b`).
   - In 8086 assembly (MASM/TASM/emu8086), `/` is only recognized by the **assembler** during compile time for constant arithmetic expressions (e.g., `MOV AX, 100 / 4` or `EQU` directives). It is computed into an immediate constant before machine code generation.
   - The CPU never sees `/`. There is no machine opcode for `register / register`.

2. **Common Syntax Pitfall (`MOV AX, BX / CX`)**:
   - Students attempting `MOV AX, BX / CX` get an assembler syntax error because registers hold runtime state that cannot be resolved at assemble-time.

3. **Runtime Hardware Division (`DIV` / `IDIV`)**:
   - 8086 hardware executes division via dedicated opcodes: `DIV` (unsigned) and `IDIV` (signed).
   - 8-bit division divides `AX` by an 8-bit register/memory operand, placing the quotient in `AL` and remainder in `AH`.
   - 16-bit division divides `DX:AX` by a 16-bit operand, placing the quotient in `AX` and remainder in `DX`.
   - Critical bug risk: Leftover values in `AH` before 8-bit division lead to arithmetic corruption or divide-by-zero/overflow exceptions (`INT 0`).

4. **Literal and Documentation Roles**:
   - `'/'`: ASCII character literal `47` (`2Fh`).
   - CLI Flags: DOS tools switch delimiter (`masm /Zi`).
   - Reference Manuals: Shorthand indicating options or pairs (`r/m8`, `DIV/IDIV`, `DX:AX`).

---

## 3. Analysis & Key Insights

1. **The Role of `JE skip` vs. `inc dl`**:
   - When `skip:` is placed **before** `inc dl`, jumping to `skip:` avoids printing `'s'` (`int 21h`), but the CPU still executes `inc dl`, turning `'s'` into `'t'`. The loop progresses normally.
   - When `skip:` is placed **after** `inc dl`, jumping to `skip:` bypasses **both** the character display (`int 21h`) AND the register increment (`inc dl`).

2. **The "Silent Loop" Failure Mode**:
   - When `DL` reaches `'s'`, `DL` is never incremented. It remains frozen at `'s'`.
   - `LOOP level` decrements `CX` and jumps back to `level`.
   - On every subsequent pass, `cmp dl, 's'` is immediately true, which again jumps over the increment to `skip:`.
   - The loop runs silently for all remaining 8 counts (`CX = 8, 7, ..., 0`) without printing or updating `DL`.
   - When `CX` hits 0, the program gracefully terminates, giving the visual impression that printing stopped at `'r'`.

## 3. Analysis & Key Insights

1. **Binary Storage in `AL`**:
   - Hardware level: Every CPU register (`AL`, `AH`, `BL`, etc.) strictly stores binary bits (`0`s and `1`s).
   - Semantic level: Both programs store raw binary numbers initially (4-bit nibbles in `5.1.asm`, 8-bit product quotient/remainder in `3.2.asm`), and then convert those numbers into binary-encoded ASCII character codes for display.

2. **Architectural Rationale for Separation Techniques**:
   - **Base-16 (Hexadecimal) in `5.1.asm`**: Because $16 = 2^4$, each hexadecimal digit maps precisely to 4 binary bits (1 nibble). Digit separation is performed using bitwise shifts (`SHR AL, 4`) and bit masks (`AND AL, 0Fh`). This takes 1–2 CPU clock cycles.
   - **Base-10 (Decimal) in `3.2.asm`**: Because 10 is not a power of 2, decimal digits do not align with bit boundaries. Digit separation requires mathematical integer division (`DIV BL`, with `BL = 10`), yielding the tens digit in `AL` (quotient) and the units digit in `AH` (remainder). This hardware microcode routine takes 80–90 clock cycles.

3. **ASCII Conversion Differences**:
   - `3.2.asm`: Decimal digits are always $0 \le d \le 9$, so direct addition of `48` (`+ '0'`) is sufficient.
   - `5.1.asm`: Hex digits span $0 \le d \le 15$. Digits $10 \le d \le 15$ require an additional `+ 7` to skip the 7 non-alphanumeric ASCII symbols between `'9'` and `'A'`.

4. **Bug Discovery in `3.2.asm`**:
   - Line 52 adds `48` to `al` before saving to `multi`, meaning the subsequent `div bl` divides $(Product + 48)$ by 10 instead of dividing the raw product by 10.
   - `AH` is not cleared before 8-bit `DIV BL`, which risks divide-by-zero/overflow exceptions (`INT 0`).

## 3. Analysis & Key Insights

1. **Eliminating Premature Conversion (`add al, 48`)**:
   - The product must remain in raw numeric binary format ($0 \dots 81$) when passed to the digit separation stage.
   - Adding 48 before `DIV BL` inadvertently computed $\lfloor (N + 48) / 10 \rfloor$, yielding corrupted digits (e.g. $12$ became $60$, displaying `60` instead of `12`).
2. **Explicit Zero-Extension for Division (`mov ah, 0`)**:
   - In 8086 architecture, `DIV r/m8` divides the whole 16-bit register pair `AX` (i.e. `AH:AL`) by the 8-bit divisor.
   - Leaving `AH` uninitialized or populated with leftover high-byte product bits risks division overflow exception (`INT 0`). Explicitly setting `mov ah, 0` ensures the dividend is purely the single-byte product.
3. **Clean Program Termination (`int 21h / ah=4Ch`)**:
   - Added standard DOS process termination to prevent CPU instruction pointer overrun into unallocated memory.
