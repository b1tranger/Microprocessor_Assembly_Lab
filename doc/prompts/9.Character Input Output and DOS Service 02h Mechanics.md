## 3. Analysis & Key Insights

1. **The DOS Service `02h` Parameter Contract**:
   - MS-DOS Service `02h` requires the ASCII character to be placed into register **`DL`** prior to issuing `INT 21h`.
   - When `INT 21h` is triggered with `AH = 02h`, the DOS ISR immediately reads the byte currently residing in `DL` and writes it to the active display output.

2. **Validation of `2.2.asm:L14-L16`**:
   - `MOV AH, 2`: Selects service `02h`.
   - `MOV DL, 32`: Loads ASCII 32 (Space character).
   - `INT 21h`: Fires the interrupt once, correctly displaying one space character.
   - **Verdict**: Fully valid, standard canonical pattern.

3. **Diagnosis of `2.1.asm:L12-L16`**:
   - Line 12 (`mov ah, 2`): Selects service `02h`.
   - Line 13 (`int 21h`): **Premature trigger bug!** `DL` has not been set yet. The CPU calls DOS to print whatever uninitialized garbage happens to be in `DL`.
   - Line 14 (`mov dl, bl`): Staging the character from `BL` into `DL`.
   - Line 15 (`int 21h`): Second trigger prints the character in `BL`.
   - **Verdict**: **Flawed / Buggy**. It invokes `INT 21h` twice, outputting two characters (an uninitialized garbage character followed by the character in `BL`).

4. **Correct Refactored Form for `2.1.asm`**:
   ```assembly
   mov ah, 2
   mov dl, bl    ; Set DL first!
   int 21h       ; Then trigger once
   ```

## 3. Analysis & Key Insights

1. **Validation Verdict: 100% VALID**:
   - This block is the textbook canonical sequence in MS-DOS real-mode assembly for reading a single character from the keyboard.

2. **Step-by-Step Architectural Mechanics**:
   - `mov ah, 1`: Staged in the upper byte of the accumulator (`AH`), signaling to DOS that Service `01h` (Keyboard Character Input with Echo) is requested.
   - `int 21h`: The CPU triggers the software interrupt to the DOS ISR. The OS blocks execution until a key is pressed, echoes the pressed key to the active display, and deposits the character's ASCII code into register **`AL`**.
   - `mov bl, al`: Copies the character from `AL` into `BL`.

3. **Why `mov bl, al` is Crucial (Accumulator Volatility)**:
   - `AL` is part of register `AX`.
   - Any subsequent DOS call (such as printing with `mov ah, 2` or exiting with `mov ah, 4ch`) or arithmetic instruction will overwrite or alter `AX`.
   - Storing the input into `BL` guarantees that the user's keystroke is not clobbered and remains available for future processing or printing.

## 3. Analysis & Key Insights

1. **Register Directionality in MS-DOS System Calls (`AH` vs. `AL`)**:
   - `mov ah, 1` does **not** store input data. `AH` functions as the **Service Selector / Command Code** passed into the DOS Interrupt Service Routine (`INT 21h`).
   - `int 21h` halts execution, waits for a keypress, echoes it to the console, and deposits the keystroke's ASCII byte into register **`AL`** (the return buffer).
   - `sub al, 48` operates on `AL` because `AL` is where DOS placed the user's keystroke. Subtracting 48 (`30h`) strips the ASCII prefix, yielding the pure numeric integer.
   - `mov num2, al` stores the resulting numeric value into memory.

2. **Bit-Width Realities of `AL`**:
   - `AL` is a full **8-bit register** ($0\text{ to }255$). It is never restricted to 4 bits.
   - The returned ASCII character byte (e.g. `'7'` = $55\text{d}$ = `0011 0111b`) is already an 8-bit value.
   - Single decimal digits ($0\text{–}9$) fit inside 4 bits ($0000b\text{–}1001b$), which is why they fit comfortably in `AL`.

3. **Handling Values Longer Than 4 Bits ($N \ge 10$)**:
   - **Single Key Limitation**: `INT 21h / AH=01h` only captures a single keypress. Typing "25" will only read `'2'`.
   - **Multi-Digit Input Loop**: Reading numbers with multiple digits requires an iterative loop that captures characters until Enter (`13`), computing $\text{Total} = (\text{Total} \times 10) + (\text{AL} - 48)$.
   - **Multi-Digit Output**: Single-digit display uses `ADD AL, 48` followed by `INT 21h / AH=02h`. Numbers $> 9$ (like the sum of marks in `4.1_CP.asm`) cannot use `ADD AL, 48`; they require `DIV 10` to separate quotient (tens) and remainder (units) into separate characters.
