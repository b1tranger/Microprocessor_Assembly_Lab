## 4. Model Response & Solution

The issue is in your **`print_hex`** procedure on line 52:

```assembly
   out:
    mov dl, al
    mov al, 02h    ; <--- BUG: This sets AL, not AH!
    int 21h
    ret
```

### Why it causes special characters:
* **DOS Service 02h (Character Output)** expects the function code in **`AH`** (`mov ah, 02h`), not `AL`.
* Because `AL` was modified instead of `AH`, `AH` remained `09h` (from line 16).
* When `int 21h` is called with `AH = 09h`, DOS treats `DX` as a pointer to a `$`-terminated string. Since `DX` only contained the character's ASCII value (e.g., `0044h`), DOS printed raw memory bytes starting from address `0044h` until it found a `$` character, printing gibberish and special characters.

---

### Additional note on label names:
`OUT` is a reserved x86 assembly instruction (used for port I/O). While some assemblers tolerate it as a label, it is best practice to rename it to something like `print_char:` or `done:` to avoid conflicts.
