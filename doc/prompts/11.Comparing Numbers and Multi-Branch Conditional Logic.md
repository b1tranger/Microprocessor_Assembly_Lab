## 3. Analysis & Key Insights

### Architectural Comparison Mechanics (`CMP` & FLAGS)
1. `CMP dest, src` executes a non-destructive subtraction: $\text{dest} - \text{src}$.
2. `dest` is preserved intact while CPU status flags (`ZF`, `SF`, `OF`, `CF`) are updated in `FLAGS`.

### Signed (`JG`/`JL`) vs. Unsigned (`JA`/`JB`) Branching
- Keyboard inputs read via `INT 21h, AH=01h` are unsigned 8-bit ASCII bytes ($0..255$).
- While ASCII digits `'0'` through `'9'` ($30\text{h}..39\text{h}$) have $\text{MSB}=0$ and behave identically in signed and unsigned jumps, extended ASCII ($\ge 80\text{h}$) is misinterpreted if signed jumps (`JG`/`JL`) are used.
- Architectural best practice dictates **`JA`/`JB`** for character comparisons.

### The "Partial Equality" Fallacy in 3-Number Comparisons
In [`9.3_alt_assignment.asm`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm):
```assembly
mov al, n1
mov ah, n2
cmp al, ah
je both_are_equal    ; FLAW: If A == B, ignores C entirely!
```
- For input $A=3, B=3, C=9$, the program outputs `" Equal values!"` despite $C=9$ being the true maximum.
- All three values are equal if and only if $(A == B) \land (B == C)$.

### Critical Bug Patterns Uncovered in Lab 9 Codes
1. **Missing `INT 21h` after `mov ah, 4ch`**:
   - Present in [`9.1.asm#L78`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.1.asm#L78), [`9.2_assignment.asm#L146`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L146), and [`9.3_alt_assignment.asm#L113`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.3_alt_assignment.asm#L113).
   - `mov ah, 4ch` does not notify DOS without `int 21h`; the CPU falls through the end of the code segment into uninitialized memory.
2. **Single-Byte String Print Hazard**:
   - In [`9.2_assignment.asm#L110-L112`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/9.2_assignment.asm#L110-L112), invoking `AH=09h` on single byte `largest db ?` causes memory leakage until a random `$` byte is reached in RAM.
3. **Illegal Identifiers Starting with Digits**:
   - Labels `1_is_big:` and `2_is_big:` violate 8086 assembler naming syntax.
4. **Undefined Symbol Reference**:
   - `jl 3_is_big` jumps to a label that is never declared.
5. **Register Overwrite & Uninitialized Reads**:
   - In [`3value_Semim.asm#L56`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/3value_Semim.asm#L56), `mov bl, al` overwrites input $A$ with input $C$.
   - In [`3value_Semim.asm#L75`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/3value_Semim.asm#L75), `cmp bl, cl` compares with uninitialized garbage in `CL`.
   - In [`3value_Semim.asm#L83`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/3value_Semim.asm#L83), `cmp bl` is illegal syntax missing a second operand.
   - In [`3value_Semim.asm#L84`](https://github.com/b1tranger/Microprocessor_Assembly_Lab/blob/main/LabCodes/lab-9_Comparing_Numbers/3value_Semim.asm#L84), `jmp b_is_big` precedes `int 21h`, bypassing string print $A$.
